# P0 功能交互设计文档

> 基于 miniops 现有「文件分发」功能的 UX 交互模式，为 5 个 P0 级提议设计具体的用户交互方案。
>
> 设计原则：**新功能尽量复用已有交互模式**（折叠卡片、checkbox 多选、SSE 进度、ConfirmDialog），让用户学会分发页操作后，其他功能零学习成本上手。

---

## 一、现有「文件分发」UX 交互梳理

### 1.1 整体布局

单页垂直线性滚动，**5 个编号区块自上而下**，用户按 1→2→3→4→5 顺序操作：

```
┌─────────────────────────────────────┐
│ 页头: 文件分发                        │
├─────────────────────────────────────┤
│ 1. 选择文件                          │  ← 文件输入
│   [添加文件] [添加文件夹]             │
│   ├ 文件/文件夹列表(分组+折叠)        │
│   └ 上传状态图标(loading/✓/✗)        │
├─────────────────────────────────────┤
│ 2. 选择目标 & Bucket                  │  ← 实例选择
│   ├ ☑ 组A (折叠/展开)                 │
│   │   ├ ☑ 实例1  bucket:[下拉选]      │
│   │   └ ☑ 实例2  bucket:[下拉选]      │
│   └ ☐ 组B                           │
├─────────────────────────────────────┤
│ 3. 目标前缀(可选)                     │  ← 前缀输入
│   [________________]                 │
├─────────────────────────────────────┤
│ 4. 已选3个实例,5个文件  [开始分发]     │  ← 提交栏
├─────────────────────────────────────┤
│ 5. 分发进度 (仅运行时/有结果时显示)    │  ← 进度
│   实例A  3/5  ███░░ [重试]           │
│   实例B  5/5  █████                  │
└─────────────────────────────────────┘
```

### 1.2 核心交互模式

| 模式 | 具体表现 |
|---|---|
| **编号线性流** | 区块用 1/2/3/4 编号，引导用户自上而下操作 |
| **折叠卡片** | 组、文件夹、进度行都可展开/收起（chevron 图标切换） |
| **Checkbox 多选** | 组级全选 + 半选(indeterminate) + 实例级勾选 |
| **内联状态** | 每个文件/实例旁直接显示状态图标（loading/✓/✗），不需点开看 |
| **SSE 实时进度** | 运行中自动推送，实例级聚合(完成数/总数 + 进度条) |
| **Toast 反馈** | 操作成功/失败用顶部 toast，不打断页面流 |
| **Modal 表单** | 实例编辑用弹窗(NuxtModal)，不跳页 |
| **确认弹窗** | 删除操作用 ConfirmDialog 二次确认 |

### 1.3 导航结构

```
侧边栏:
  总览          -> /
  实例          -> /groups
  运维
    文件分发    -> /ops/dispatch
```

## 二、导航结构变更预览

### 2.1 导航架构决策：操作能力驱动

> **决策**：侧边栏以"操作能力"为主线划分，不以"实例->bucket"链路划分。

**决策理由：**

miniops 的产品定位是**批量运维平台**，核心价值是"一次操作 N 个实例"。两种划分方式在关键场景下的表现对比：

| 场景 | 操作能力驱动 | 实例->bucket 链路驱动 |
|---|---|---|
| 1 个文件分发到 5 个站 | 分发页 -> 选文件 -> 勾 5 个实例 -> 提交。一次完成 | 需逐个进入 5 个实例 -> bucket -> 上传。5 次操作 |
| 回看上次分发结果 | 分发历史页。天然适配 | 跟实例->bucket 链路无关，无处安放 |
| 连通性批量测试 | 实例管理 -> 测试全部。天然适配 | 需逐个实例点进去测。别扭 |
| 查看某实例 bucket 内容 | 对象浏览 -> 选实例 -> 选 bucket。两步选择 | 侧边栏直接点实例 -> bucket。一步到位 |
| 50 个实例 × 3 个 bucket | 侧边栏 5 个菜单项，稳定 | 侧边栏 150 项，爆炸 |

结论：**批量操作是主线**（分发、历史、测试都是跨实例的），操作能力驱动天然适配。单实例精细操作（浏览、删单个文件）频率较低，通过在实例管理页的实例行增加快捷入口（如"浏览对象"按钮）提供捷径，不干扰主线。

### 2.2 导航结构

P0 功能落地后的侧边栏导航：

```
侧边栏:
  总览          -> /
  实例          -> /groups        (实例行新增"浏览对象"快捷按钮)
  运维
    文件分发    -> /ops/dispatch  (新增模式切换: 本地上传 | 实例同步)
    对象浏览    -> /ops/browser   (新增)
    分发历史    -> /ops/history   (新增)
```

### 2.3 实例管理页的快捷入口

实例管理页 `/groups` 中，每个启用的实例行增加"浏览对象"按钮，点击直接跳转到对象浏览页并预选该实例：

```
┌ 实例行 ─────────────────────────────────────────────────────────┐
│ 站A  10.0.0.1:9000  [在线·凭据有效]  [测试][浏览][禁用][编辑][复制][删除] │
│                                           ↑ 新增快捷入口             │
└──────────────────────────────────────────────────────────────────┘
```

- 点击「浏览」-> 跳转 `/ops/browser?instanceId=xxx` -> 自动选中该实例并加载 bucket 列表
- 降低单实例操作的操作路径，同时不污染侧边栏导航

## 三、各提议交互设计

### 提议 11：连通性测试增强（凭据验证）

**改动范围最小**——复用现有实例管理页的测试交互，只增强结果展示。不新增页面、不新增路由。

#### 3.1.1 单实例测试结果

实例管理页 `/groups` 的"测试"按钮不变，连通性列从两态升级为三态：

```
当前结果:        [在线] 23ms              ← 只有两态

增强后结果:
  ✅ [在线·凭据有效] 23ms     ← 绿色 badge + latency
  ⚠️ [在线·凭据无效] 23ms     ← 橙色 badge + tooltip: "Access Denied"
  ❌ [不可达] 超时             ← 红色 badge + tooltip: 错误详情
  ⏳ spinner                   ← 测试中(不变)
```

#### 3.1.2 批量测试结果

"测试全部"完成后，组标题旁显示聚合摘要：

```
┌ 组A ────────────────────────────────────────────────┐
│ ☑ 组A  3个启用  [2在线·1离线]  [测试全部] [加实例]   │
│                      ↑ 新增聚合 badge                │
│ ┌──────────────────────────────────────────────────┐ │
│ │ 实例    endpoint          连通性                   │ │
│ │ 站A     10.0.0.1:9000     [在线·凭据有效] 12ms   │ │
│ │ 站B     10.0.0.2:9000     [在线·凭据无效] ⚠️     │ │  ← 标橙
│ │ 站C     10.0.0.3:9000     [不可达] ❌            │ │  ← 标红
│ └──────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

#### 3.1.3 分发页前置预检

分发页 Section 2 中，选中实例后加载 bucket 时顺带做凭据预检：

```
  ☑ 实例 1  http://10.24.0.10:9000
                                      ⚠️ 凭据无效    ← inline 警告
                                      bucket: [下拉选]
```

凭据无效的实例：
- 显示橙色警告标识
- bucket 下拉仍可手动输入（不阻断，但提醒用户）
- 提交分发时 toast 提示"部分实例凭据可能无效"

#### 3.1.4 设计要点

- 零新增页面、零新增路由，纯增强现有连通性列
- 三态用颜色区分：绿(成功)/橙(凭据问题)/红(不可达)，与现有 badge 风格一致
- 错误详情走 tooltip（hover 查看），不占列宽
- "测试全部"后组标题显示聚合状态，一眼看出组内健康度

### 提议 1：对象浏览器（Object Browser）

**新增页面** `/ops/browser`，复用折叠卡片 + 列表交互模式。

#### 3.2.1 页面整体布局

```
┌ 对象浏览 ───────────────────────────────────────────┐
│                                                      │
│ ┌ 第一步: 选实例 ──────────────────────────────────┐ │
│ │ [实例下拉选择 ▾]  或  搜索...                     │ │
│ │  选定后自动加载 bucket 列表                        │ │
│ └──────────────────────────────────────────────────┘ │
│                                                      │
│ ┌ 第二步: 选 Bucket ───────────────────────────────┐ │
│ │ [Bucket 下拉 ▾]  ← 从 ListBuckets 获取            │ │
│ └──────────────────────────────────────────────────┘ │
│                                                      │
│ ┌ 第三步: 浏览对象 ────────────────────────────────┐ │
│ │ 面包屑: config/ > 2025Q3/ >                      │ │  ← 前缀层级导航
│ │ [全选] [删除选中(2)]           [刷新]             │ │
│ │ ┌──────────────────────────────────────────────┐ │ │
│ │ │ ☐ 📁 sub-folder/           -     2025-07-15  │ │ │  ← CommonPrefixes
│ │ │ ☐ 📄 config.json         2.1KB  2025-07-15   │ │ │  ← Contents
│ │ │ ☐ 📄 device.json         4.5KB  2025-07-14   │ │ │
│ │ │ ☐ 📄 layout.xml          1.2KB  2025-07-14   │ │ │
│ │ └──────────────────────────────────────────────┘ │ │
│ └──────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

#### 3.2.2 对象行操作

hover 时浮现操作按钮，保持列表简洁：

```
☐ 📄 config.json  2.1KB  2025-07-15
                   [下载] [删除]    ← hover 时浮现
```

#### 3.2.3 下载交互

- 点击「下载」→ 后端流式代理（签名 GET 对象 → sendStream 转发给浏览器），兼容现场内网环境
- 不弹窗、不跳页，触发即下载
- 另提供「复制链接」按钮：后端生成预签名 GET URL（默认 15 分钟有效），复制到剪贴板供外部工具使用
- 大文件走后端流式管道，不缓冲整个文件到内存

#### 3.2.4 前缀层级导航（面包屑）

S3 没有"文件夹"概念，用 `CommonPrefixes` 模拟虚拟目录：

```
点击 📁 sub-folder/ 行:
  → 面包屑追加一层: config/ > sub-folder/
  → 加载该前缀下的对象列表

点击面包屑任意层级:
  → 回退到该层级，加载对应对象列表
```

#### 3.2.5 加载态与空状态

```
选实例后:    bucket 下拉显示 spinner
选 bucket 后: 对象列表区域显示 skeleton/spinner
列表为空:    "该路径下暂无对象"（复用现有空状态样式）
```

#### 3.2.6 设计要点

- 三步线性流与分发页风格一致（选实例→选 bucket→操作）
- 面包屑导航解决 S3 前缀层级问题，不引入树形控件
- 对象行操作按钮 hover 浮现，保持列表简洁
- 下载默认走后端流式代理（内网友好），预签名 URL 作为辅助
- 删除单删+批删都在本提议实现，提议 4 后续做跨实例/按前缀独立清理入口
- 详细设计见 P0_DESIGN_01_BROWSER.md

- 批量删除走进度展示（复用 SSE），不是一次性 fire-and-forget
- 删除后自动刷新列表，保持数据一致

#### 3.4.2 两级展开：任务 → 实例 → 文件

任务卡片默认折叠，展开后显示实例级聚合；实例行可再展开显示文件级明细：

```
点击任务卡片 [展开 ▾]:
  → 显示实例级结果表

  实例 1  5/5  0    3.2s        [▾]
    ✅ config.json          320ms
    ✅ device.json          280ms
    ✅ layout.xml           150ms
    ✅ backup.tar           1.2s
    ✅ rules.json           95ms

  实例 2  4/5  1    2.8s  [重试] [▾]
    ✅ config.json          310ms
    ✅ device.json          275ms
    ✅ layout.xml           145ms
    ❌ backup.tar           超时      ← tooltip: "请求超时"
    ✅ rules.json           90ms
```

#### 3.4.3 「复制配置」交互

```
点击 [复制配置]
  → Toast "配置已复制，请重新上传文件"
  → 跳转到分发页 /ops/dispatch
  → 分发页自动预填: 选中的实例 + bucket + 前缀
  → 文件区域显示提示: "请重新上传文件（历史文件已清理）"
```

> 注意：暂存文件有 TTL 限制（默认 24h），历史任务中的文件可能已被清理，因此"复制配置"只恢复目标配置，文件需重新上传。

#### 3.4.4 「重试」交互

- **单实例重试**：点击实例行的 [重试] → 只重试该实例的失败文件 → inline 进度（复用 SSE）
- **全部重发**：点击 [全部重发] → 跳转分发页，预填所有失败实例 + 对应文件 → 用户确认后提交

#### 3.4.5 筛选交互

| 筛选项 | 选项 |
|---|---|
| 状态 | 全部 / 全部成功 / 有失败 / 全部失败 |
| 组 | 列出所有实例组 |
| 时间 | 近 1 天 / 7 天 / 30 天 / 全部 |

#### 3.4.6 设计要点

- 任务卡片折叠展开，与分发页进度视图风格统一
- 两级展开：任务→实例→文件，逐层深入
- 失败项突出显示，重试操作就近放置
- "复制配置"实现历史任务到新分发的衔接，但文件需重传（TTL 限制）
- 分页避免大量历史记录一次加载


#### 3.5.3 Section 2-5 完全复用

```
2. 选择目标 & Bucket  ← 与现有完全一致
3. 目标前缀           ← 与现有完全一致
4. [开始同步]         ← 按钮文案随模式切换: "开始分发" → "开始同步"
5. 同步进度           ← 复用现有进度视图(SSE)
```

#### 3.5.4 模式切换交互

```
点击 ( ) 实例同步:
  → Section 1 内容从"文件上传区"切换为"源实例选择区"
  → Section 2/3 不变（目标选择逻辑通用）
  → Section 4 按钮文案: "开始分发" → "开始同步"
  → Section 5 进度视图不变（复用 SSE）
  → 如有未分发文件: 弹出确认 "切换模式将清空已选文件，确认?"
```

#### 3.5.5 源对象加载交互

```
选源实例 → bucket 下拉自动加载(ListBuckets)
选 bucket + 填前缀 → 点 [加载对象列表] → 后端 ListObjectsV2
  → loading: spinner
  → 空列表: "该前缀下无对象"
  → 有结果: 显示 checkbox 列表，支持全选
```

#### 3.5.7 设计要点

- 不新增页面，在分发页内切换模式，降低学习成本
- Section 2-5 完全复用，只有 Section 1 的输入方式变了
- 源对象列表与对象浏览器的对象列表风格一致（checkbox + 文件图标 + 大小）
- 进度视图顶部增加源信息行，让用户知道"从哪同步到哪"
- 大文件流式传输，前端进度展示与现有分发一致
