# 提议 1 交互设计文档：对象浏览器（Object Browser）

> **目标**：让用户在 miniops 平台内直接查看 MinIO 实例的 bucket 内容，完成浏览、下载、删除闭环，无需另开 MinIO Console 或 mc 客户端。
>
> 本文档在 `P0_INTERACTION_DESIGN.md` 第 3.2 节概要设计的基础上细化，含具体交互决策、状态流转和边界处理。

---

## 一、设计目标与约束

### 1.1 解决的痛点

当前 miniops 只能"往 MinIO 推文件"，无法"看 MinIO 里有什么"。分发后用户无法在平台内确认目标 bucket 是否已有同名文件、前缀路径是否正确，必须另开 MinIO Console，操作割裂。

### 1.2 设计原则

- **复用现有交互模式**：三步线性流（选实例 -> 选 bucket -> 操作）与分发页一致，用户学会分发页后零学习成本上手。
- **单实例操作场景**：对象浏览本质是"逐个实例查看"，不是批量操作，因此用单实例选择而非批量勾选。
- **安全优先**：删除操作必须二次确认并显示完整对象列表；下载走后端代理，密钥不暴露给浏览器。

### 1.3 已确认的决策

| 决策点 | 结论 | 理由 |
|---|---|---|
| 删除范围 | 单删 + 批删都在本提议实现 | 提议 4 后续做"跨实例/按前缀"的独立批量清理入口，不重复浏览器内的多选删除 |
| 下载方式 | 后端流式代理为默认 + "复制预签名 URL"辅助 | 现场浏览器通常在内网，直连 MinIO 可能不通；后端代理兼容性最好 |
| 路由风格 | 单实例操作，传单个 `instanceId` | 浏览是逐个实例查看，与批量分发场景不同 |
| XML 解析 | 正则提取，不引第三方库 | 与现有 `parseBucketNames` 风格一致，零新增依赖 |
| 分页 | 固定 `maxKeys=1000` + "加载更多"按钮 | S3 ListObjectsV2 单页上限 1000，加载更多即可覆盖大 bucket |
| 前缀导航 | 面包屑逐级导航 + 前缀输入框直接跳转 | 面包屑解决层级回退，输入框解决深层路径直达 |

## 二、页面整体布局

### 2.1 路由与入口

- **页面路由**：`/ops/browser`
- **侧边栏导航**：`运维 > 对象浏览`（`AppLayout.vue` 的 navItems 新增一项）
- **实例管理页快捷入口**：`/groups` 页每个启用实例行新增"浏览"按钮，点击跳转 `/ops/browser?instanceId=xxx`，自动预选该实例

### 2.2 三步线性流布局

```
┌ 对象浏览 ───────────────────────────────────────────────────────┐
│                                                                    │
│ ┌ 第一步: 选实例 ──────────────────────────────────────────────┐ │
│ │ [实例下拉选择 ▾]                                              │ │
│ │  选定后自动加载 bucket 列表                                    │ │
│ └────────────────────────────────────────────────────────────────┘ │
│                                                                    │
│ ┌ 第二步: 选 Bucket ───────────────────────────────────────────┐ │
│ │ [Bucket 下拉 ▾]  ← 从 ListBuckets 获取                        │ │
│ └────────────────────────────────────────────────────────────────┘ │
│                                                                    │
│ ┌ 第三步: 浏览对象 ────────────────────────────────────────────┐ │
│ │ 面包屑: config/ > 2025Q3/        [前缀输入框] [跳转]  [刷新]  │ │
│ │ ☑ 全选  已选 2/4 个              [下载选中] [删除选中(2)]     │ │
│ │ ┌──────────────────────────────────────────────────────────┐ │ │
│ │ │ ☐ 📁 sub-folder/           -     2025-07-15             │ │ │  ← CommonPrefixes
│ │ │ ☐ 📄 config.json         2.1KB  2025-07-15  [下载][删除] │ │ │  ← Contents
│ │ │ ☐ 📄 device.json         4.5KB  2025-07-14  [下载][删除] │ │ │
│ │ │ ☐ 📄 layout.xml          1.2KB  2025-07-14  [下载][删除] │ │ │
│ │ └──────────────────────────────────────────────────────────┘ │ │
│ │                                                  [加载更多]   │ │  ← 有 continuationToken 时
│ └────────────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────────┘
```

### 2.3 布局规则

- 三步区块自上而下排列，每步有编号标题，与分发页风格一致
- 第一步未完成时，第二步、第三步灰显不可操作
- 第二步未完成时，第三步灰显不可操作
- 选定实例 + bucket 后，第三步自动加载根前缀对象列表

## 三、核心交互流程

### 3.1 选实例

```
页面加载
  ├ URL 含 ?instanceId=xxx -> 自动选中该实例
  └ URL 无参数 -> 实例下拉为空，等待用户选择

实例下拉选项来源:
  GET /api/groups -> 展开所有 enabled 实例
  按组分组展示（NuxtSelectMenu 的 groups 属性）
  格式: "组名 / 实例名 (endpoint)"

选定实例后:
  -> 自动触发 bucket 列表加载
  -> bucket 下拉显示 spinner
  -> 加载完成: 下拉填充 bucket 名列表
  -> 加载失败: 下拉为空 + 内联错误提示 + 手动输入兜底
```

**实例下拉选项设计**：

```
┌ 实例下拉 ▾ ──────────────────────┐
│ 1号线                            │  ← 组标签（不可选）
│   人民广场站 (10.24.0.10:9000)   │
│   南京东路站 (10.24.0.11:9000)   │
│ 2号线                            │
│   中山公园站 (10.24.0.20:9000)   │
└──────────────────────────────────┘
```

### 3.2 选 Bucket

```
选定实例后自动加载:
  POST /api/instances/buckets { instanceIds: [选中的instanceId] }
  -> 取返回值中该实例的 buckets 数组
  -> 填充 bucket 下拉

bucket 加载失败（凭据无效等）:
  -> 下拉区域显示: ⚠️ 加载失败: <error>
  -> 旁边提供手动输入框（兜底，允许直接输入 bucket 名）
  -> 不阻断后续操作（用户可能知道 bucket 名）

选定 bucket 后:
  -> 自动触发对象列表加载（prefix="" 根路径）
```

### 3.3 浏览对象

```
选定 bucket 后自动加载:
  POST /api/instances/objects/list
    { instanceId, bucket, prefix: "", delimiter: "/" }
  -> 返回 { objects: [...], commonPrefixes: [...], isTruncated, continuationToken }

列表渲染顺序:
  1. CommonPrefixes（虚拟文件夹 📁）排在前面
  2. Contents（对象 📄）排在后面
  3. 同类内按名称排序

每行显示:
  [checkbox] [图标] [名称]  [大小]  [修改时间]  [行操作]
```

## 四、前缀层级导航（面包屑）

### 4.1 S3 前缀模型

S3 没有真正的"文件夹"，用 `delimiter="/"` + `CommonPrefixes` 模拟虚拟目录：

```
请求: prefix="config/", delimiter="/"
响应:
  <CommonPrefixes><Prefix>config/2025Q3/</Prefix></CommonPrefixes>  ← 子文件夹
  <Contents><Key>config/config.json</Key>...</Contents>             ← 该层文件
```

### 4.2 面包屑交互

```
当前前缀: config/2025Q3/

面包屑显示:
  [根] > config/ > 2025Q3/

点击 [根]:
  -> prefix="", 加载根级列表
点击 [config/]:
  -> prefix="config/", 加载该层列表
点击 [2025Q3/]:
  -> 当前层，无操作（高亮）

点击 📁 文件夹行:
  -> prefix 追加该文件夹名
  -> 面包屑追加一层
  -> 加载该前缀下对象列表
```

### 4.3 前缀输入框跳转

面包屑右侧提供前缀输入框，支持直接跳转到任意前缀：

```
[前缀: ________________] [跳转]

输入 "config/2025Q3/" 后点击跳转:
  -> prefix="config/2025Q3/"
  -> 面包屑更新为: [根] > config/ > 2025Q3/
  -> 加载该前缀下对象列表

输入不带尾斜杠的 "config":
  -> 后端自动补全为 "config/"
  -> 正常加载
```

**输入框校验**：
- 空输入 -> 跳转到根（`prefix=""`）
- 输入自动做 `sanitizeObjectKey` 清洗（防 `..` 路径遍历，复用 `server/utils/uploads.ts` 中的逻辑）

```

│  │       │          │       │               └ hover 时浮现

│  │       │          └ 文件大小（人类可读：B/KB/MB/GB）

```

### 5.2 文件大小格式化

```
< 1KB    -> "xxx B"
< 1MB    -> "xx.x KB"
< 1GB    -> "xx.x MB"
≥ 1GB    -> "xx.x GB"
```

### 5.3 图标规则

| 类型 | 图标 | 判断依据 |
|---|---|---|
| 虚拟文件夹 | `i-lucide-folder` | `CommonPrefixes` 项 |
| 图片 | `i-lucide-image` | Content-Type 以 `image/` 开头 |
| 文本 | `i-lucide-file-text` | Content-Type 以 `text/` 开头或为 `application/json` |
| 视频 | `i-lucide-file-video` | Content-Type 以 `video/` 开头 |
| 其他文件 | `i-lucide-file` | 其他 |

### 5.4 对象名显示

显示 Key 去掉当前 `prefix` 后的部分：
- 当前 `prefix="config/2025Q3/"`，对象 Key 为 `config/2025Q3/device.json`
- 显示名：`device.json`

如果去掉前缀后仍含 `/`（理论不会，因为 `delimiter="/"` 已分割），则显示最后一段。

## 六、下载交互

### 6.1 默认方式：后端流式代理

点击「下载」按钮：
```
1. 前端触发: window.location = `/api/instances/objects/download?instanceId=xxx&bucket=yyy&key=zzz`
2. 后端:
   - 从 store 查出实例凭据
   - 用 signRequest 签名 GET /{bucket}/{key}
   - 获取 MinIO 响应的 ReadableStream
   - 设置 Content-Disposition: attachment; filename="<最后一段文件名>"
   - 设置 Content-Type（透传 MinIO 返回的）
   - 设置 Content-Length（透传）
   - 流式转发给浏览器
3. 浏览器: 触发原生下载（下载栏显示进度）
```

**不弹窗、不跳页**，触发即下载。

### 6.2 辅助方式：复制预签名 URL

对象行操作区另提供「复制链接」按钮（hover 时与下载/删除并列）：

```
点击 [复制链接]:
  -> POST /api/instances/objects/presign { instanceId, bucket, key }
  -> 后端生成预签名 GET URL（默认有效期 15 分钟）
  -> 返回 { url: "https://..." }
  -> 前端复制到剪贴板
  -> Toast: "下载链接已复制（15 分钟内有效）"
```

**用途**：用户可在外部工具（curl、wget）中下载，或粘贴到浏览器直接打开。

### 6.3 批量下载（ZIP 打包）

勾选多个对象/文件夹后点击「下载选中」，后端递归收集所有对象 key，流式 ZIP 打包后返回：

```
点击 [下载选中(N)]:
  1. 前端 POST /api/instances/objects/download-batch
       { instanceId, bucket, keys: [...], prefixes: [...] }
  2. 后端:
     a. 合并 keys + 递归列出 prefixes 下的全部 key（delimiter=""），用 Set 去重
     b. 检查上限：对象数 ≤ 1000、总大小 ≤ 500MB
     c. 创建 archiver ZIP 流，pipe 到 HTTP 响应
     d. 逐个 GetObject -> archiver.append(stream, { name: key })
     e. Content-Disposition: attachment; filename="miniops-download-<timestamp>.zip"
  3. 浏览器: 触发下载一个 .zip 文件
```

#### 6.3.1 ZIP 内目录结构

ZIP 内保持对象在 MinIO 中的原始 key 作为路径：

```
选中：
  📁 config/        -> config/a.json, config/sub/b.xml ...
  📄 device.json    -> device.json
  📄 layout.xml     -> layout.xml

ZIP 内结构：
  config/a.json
  config/sub/b.xml
  device.json
  layout.xml
```

#### 6.3.2 安全限制

- 对象数量上限 **1000 个**（ZIP 打包比删除更重，收紧上限）
- 总大小上限 **500MB**（避免后端长时间中转和带宽压力）
- 超出任一上限时返回错误，前端 Toast 提示：
  - "选中内容过多（N 个对象 > 1000），请缩小范围"
  - "选中内容过大（XMB > 500MB），请用 mc 客户端下载"

#### 6.3.3 下载进度

- 后端无法预知 ZIP 最终大小（逐个流式拉取），无法设 `Content-Length`
- 浏览器下载栏显示“未知大小”，但下载正常进行
- 前端在按钮上显示 loading spinner，直到浏览器开始下载后重置

#### 6.3.4 混合选中场景

选中含文件夹和对象混合时，下载按钮始终显示（与删除一致）：

```
选中 📁 config/ + 📄 device.json:
  -> 后端递归列出 config/ 下全部 key
  -> 合并 device.json
  -> 去重后统一 ZIP 打包
```

- "此操作不可恢复"警告

### 7.3 删除执行

```
点击 [确认删除]:
  -> 按钮变为 loading 状态（spinner + "删除中..."）
  -> POST /api/instances/objects/delete
       { instanceId, bucket, keys: ["config.json", "device.json", ...] }
  -> 后端调用 deleteObjects()（S3 DeleteMultipleObjects）
  -> 返回 { deleted: [...], errors: [{ key, error }] }

  成功:
    -> Toast: "已删除 3 个对象"
    -> 对象列表自动刷新（重新加载当前前缀）

  部分失败:
    -> Toast: "已删除 2 个对象，1 个失败"
    -> 失败的对象行标红 + tooltip 显示错误
    -> 成功删除的从列表移除

  全部失败:
    -> Toast: "删除失败: <error>"
    -> 列表不变
```

### 7.4 删除虚拟文件夹（递归删除）

虚拟文件夹（CommonPrefixes）本身不是真实对象，但可以递归删除其下所有对象。选中文件夹后点击删除，后端先按前缀列出所有对象再批量删除。

#### 7.4.1 确认弹窗

```
选中含 📁 sub-folder/ + 📄 config.json -> 点击删除:

┌ 确认删除 ──────────────────────────────────────────┐
│                                                      │
│ ⚠️ 即将删除 1 个对象 + 1 个文件夹                      │
│                                                      │
│ 文件夹（将递归删除其下所有对象）:                       │
│   • 📁 sub-folder/                                    │
│                                                      │
│ 对象:                                                 │
│   • config.json (2.1KB)                              │
│                                                      │n│ 目标: 人民广场站 / config                            │
│                                                      │
│ 此操作不可恢复。                                       │
│                                                      │
│              [取消]  [确认删除]                       │
└──────────────────────────────────────────────────────┘
```

#### 7.4.2 删除执行

```
点击 [确认删除]:
  -> 按钮变为 loading 状态（spinner + "删除中..."）
  -> POST /api/instances/objects/delete
       { instanceId, bucket, keys: ["config.json"], prefixes: ["sub-folder/"] }
  -> 后端处理:
     1. 对每个 prefix 调 listObjects（delimiter="", 递归列出）分页收集全部 key
     2. 合并 keys + 递归列出的 key，分批调 DeleteMultipleObjects（每批 1000 个）
     3. 汇总 deleted / errors 返回
  -> 返回 { deleted: [...], errors: [{ key, error }] }

  成功:
    -> Toast: "已删除 N 个对象"
    -> 对象列表自动刷新

  部分失败:
    -> Toast: "已删除 N 个对象，M 个失败"
    -> 失败的对象行标红

  文件夹过大:
    -> 后端递归列出超过 10000 个对象时返回错误提示
    -> Toast: "文件夹下对象过多（>10000），请缩小范围后重试"
```

#### 7.4.3 安全限制

- 递归列出上限 **10000 个对象**：防止误删超大规模文件夹导致长时间阻塞
- 超出上限时拒绝删除并提示用户缩小范围
- 删除确认弹窗中**明确标注文件夹为递归删除**，与普通对象区分

## 八、多选交互

### 8.1 全选与半选

```
表头 checkbox 状态:
  未选任何    -> ☐ 空选
  选了部分    -> ☑ 半选（indeterminate）
  全选        -> ☑ 全选

点击表头 checkbox:
  全选/空选 -> 切换为反状态
  半选     -> 切换为全选
```

### 8.2 选择范围

- 多选对当前列表页生效，**对象和虚拟文件夹均可选**
- 切换前缀（进入文件夹或回退）时，清空已选
- "加载更多"追加新页时，已选保留，新页默认未选
- 文件夹选中后可用于删除（递归删除）和下载（ZIP 打包递归下载）

### 8.3 选择计数

```
未选:           [全选]                    [刷新]
选了 2 个对象:   ☑ 已选 2 项  [下载选中(2)] [删除选中(2)]  [刷新]
选了含文件夹:   ☑ 已选 1 对象 + 1 文件夹  [下载选中] [删除选中]  [刷新]
                                              ↑ 文件夹和对象混合时可下载（ZIP 打包）
```

## 九、加载态与空状态

### 9.1 各阶段加载态

| 阶段 | 加载中 | 完成 | 失败 |
|---|---|---|---|
| 选实例 | 实例下拉 spinner（首次加载组数据时） | 下拉填充实例列表 | Toast: "加载实例列表失败" |
| 选 Bucket | bucket 下拉 spinner | 下拉填充 bucket 名 | ⚠️ 错误提示 + 手动输入框兜底 |
| 加载对象 | 列表区域 skeleton/spinner | 显示对象列表 | 列表区域显示错误 + [重试] 按钮 |
| 加载更多 | 按钮变 spinner | 追加新行 | Toast: "加载更多失败" |

## 十、错误处理

### 10.1 网络错误

```
实例不可达:
  -> bucket 加载失败: ⚠️ "连接失败" + [重试]
  -> 对象列表加载失败: 错误区域 + [重试]

请求超时:
  -> 对象列表加载: "请求超时" + [重试]
  -> 下载: 浏览器原生下载失败提示
```

### 10.2 权限错误

```
403 Access Denied（凭据无效）:
  -> bucket 加载: ⚠️ "凭据无效 (403)" + 手动输入兜底
  -> 对象列表: "凭据无效，无法访问该 Bucket" + [返回选实例]
  -> 删除/下载: Toast: "凭据无效，操作失败"

404 NoSuchBucket:
  -> 对象列表: "Bucket 不存在" + [返回选 Bucket]
```

### 10.3 删除部分失败

```
3 个对象删除，1 个失败:
  -> Toast: "已删除 2 个对象，1 个失败"（warning 色）
  -> 失败对象行标红，hover 显示错误
  -> 成功对象从列表移除
```

## 十一、URL 状态同步

页面状态通过 URL query 参数同步，支持分享链接和浏览器前进/后退：

```
/ops/browser?instanceId=inst-xxx&bucket=config&prefix=config/2025Q3/

参数:
  instanceId  -> 选中的实例
  bucket      -> 选中的 bucket
  prefix      -> 当前前缀（URL 编码）

行为:
  - 实例/bucket/前缀变化时更新 URL（replaceState，不触发页面跳转）
  - 浏览器前进/后退时读取 URL 恢复状态
  - 从实例管理页"浏览"按钮跳转时带 instanceId 参数
```

## 十三、设计要点总结

1. **三步线性流**与分发页风格一致，降低学习成本
2. **面包屑 + 前缀输入框**双重导航，兼顾层级回退和深层直达
3. **后端流式代理**为下载默认方式，兼容现场内网环境
4. **删除二次确认**显示完整对象列表 + 总大小 + 目标信息，防误删
5. **文件夹递归删除**：选中虚拟文件夹后可递归删除其下所有对象，含 10000 个对象上限保护
6. **混合批量下载**：选中对象和文件夹可一起 ZIP 打包下载，保留目录结构，含 1000 个对象 / 500MB 上限保护
7. **URL 状态同步**支持分享链接和浏览器前进/后退
8. **单实例操作**，与批量分发场景区分，路由用单数 `instanceId`
