# 任务执行器技术设计

- **实现**: `server/utils/executors/`（dispatch / upload / copy / move）
- **框架**: [统一任务架构.md](统一任务架构.md)

四类操作均为 `TaskExecutor` 闭包：`createXxxExecutor(params) → { execute(task, emit, isCancelled) }`，参数在创建时捕获。

```ts
execute(task: Task, emit: (e: TaskEvent) => void, isCancelled: () => boolean): Promise<void>
```

---

## 1. DispatchExecutor（分发）

**进度**：`InstanceProgress[]`（`instanceId → { objectKey → FileResult }`）。

| 项 | 行为 |
|----|------|
| 并发 | 实例维度并发池（`DISPATCH_CONCURRENCY`，默认 5）；实例内文件串行 |
| 上传 | `readFile` Buffer + `uploadObjectStream` 单次 PUT |
| key | `fullKey = sanitize(prefix) + '/' + objectKey` |
| Content-Type | `inferContentType(objectKey)` |
| 取消 | 每文件开始前检查；未开始 `skipped`；当前 PUT 跑完 |
| 暂存清理 | `execute` 结束删除对应暂存（try-finally） |
| 实例缺失 | 该实例文件全部 `failed: 实例不存在`，不影响其他实例 |

SSE `progress` 携带 `instanceId`，供前端定位实例行。

---

## 2. UploadExecutor（上传）

单实例上传，进度为 `FlatFileProgress`（`objectKey → FileResult`）。上传循环与 Dispatch 同构：`readFile` + 单次 PUT + `inferContentType`；取消与暂存清理策略相同。

---

## 3. CopyExecutor（复制）

### 3.1 目标 key（`computeTargetKey`）

源前缀剥离后拼接目标前缀：

```text
sourcePrefix = 'data/',  key = 'data/a/b.txt',  targetPrefix = 'backup'
→ relativeKey = 'a/b.txt'
→ targetKey   = 'backup/a/b.txt'
```

- `key` 以 `sourcePrefix` 开头 → 剥前缀得 `relativeKey`
- 否则 → 完整 `key` 作为 `relativeKey`
- `targetPrefix` 去掉尾部 `/` 后拼接；目标前缀为空则 `targetKey = relativeKey`

### 3.2 流程

1. 收集：显式 `keys` + `prefixes` 递归展开（`collectObjectsByPrefixes`，上限 `COPY_MOVE_MAX_OBJECTS`）
2. 串行复制：`inferContentType` → `copyObjectStream`
   - **同 endpoint**：S3 `CopyObject`
   - **跨实例**：GetObject → Buffer → PutObject
3. 单文件失败不中断；仅成功 key 进入 `copiedKeys`

跨实例使用 Buffer：SDK 对 Node Readable 默认 chunked（无 Content-Length），需缓冲后 PUT；内存峰值约为单文件大小。

### 3.3 取消

prefix 收集循环、文件复制循环均在每项开始前检查 `isCancelled()`。

### 3.4 行为边界

| 情况 | 行为 |
|------|------|
| 目标同名 | 覆盖 |
| key 不在 sourcePrefix 下 | 完整 key 拼进 targetPrefix |
| 超大对象（跨实例） | 整文件入内存 |

## 4. MoveExecutor（移动）

复制成功后删除源对象。**非原子**：中断时可能目标与源同时存在。

### 4.1 阶段

```text
copying  → copyObjectsPhase，得到 copiedKeys，emit phase
deleting → deleteObjects(copiedKeys)，写 sourceDelete*
```

`task.currentPhase: 'copying' | 'deleting'`，经 `phase` 事件同步前端。

### 4.2 FileResult（move）

```ts
status: 'success' | 'failed' | 'running' | 'pending' | 'skipped'  // 复制结果
sourceDeleteStatus?: 'deleted' | 'delete-failed'
sourceDeleteError?: string
```

| sourceDeleteStatus | 含义 |
|--------------------|------|
| `undefined` | 未删除源（未进入删除阶段，或复制失败） |
| `'deleted'` | 源已删除 |
| `'delete-failed'` | 源删除失败，见 `sourceDeleteError` |

移动成功 ⇔ 复制 `success` 且 `sourceDeleteStatus === 'deleted'`。

### 4.3 删源

`deleteObjects`（DeleteMultipleObjects，每批 ≤1000）批量删除 `copiedKeys`，按返回写 `sourceDeleteStatus`。

### 4.4 取消

复制阶段同 copy；删除阶段不回滚已发出的删除。

---

## 5. 进度模型对照

| 操作 | 结构 | 特有字段/事件 |
|------|------|----------------|
| dispatch | `instanceProgress[]` | `progress.instanceId` |
| upload | `fileProgress` | — |
| copy | `fileProgress` | — |
| move | `fileProgress` + `currentPhase` | `phase`；`sourceDelete*` |

收尾将 `pending` 计入 `skipped`。

## 6. 公共约定

1. 上传/分发结束清理暂存文件
2. 取消仅在文件边界生效
3. 状态变更必 `emit('progress', …)`
4. 错误文案经 `formatExecError` / `formatS3Error`
