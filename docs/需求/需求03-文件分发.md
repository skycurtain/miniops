# 文件分发需求

> 对应功能：将本地文件/文件夹批量分发到多个 MinIO 实例。

## 1. 概述

用户将本地文件/文件夹批量上传到多个 MinIO 实例的目标 bucket。

与实例访问页内上传的区别：

| 维度 | 实例访问页内上传 | 文件分发（本需求） |
| --- | --- | --- |
| 目标 | 单实例、当前浏览的 bucket/前缀 | 多实例、各自指定 bucket、统一前缀 |
| 路径 | 暂存磁盘 + 后端异步上传 | 暂存磁盘 + 分发流水线 |
| 定位 | 浏览时的即时补传 | 批量推送的独立操作 |
| 入口 | 对象浏览器工具栏「上传」对话框 | 独立页面 |

两者在统一任务架构下共享暂存管理和 TaskManager（见 §9），上传本质是"单实例分发"。

## 2. 页面布局

分发页面为独立页面，采用**左右双栏布局**：

```
┌─────────────┬──────────────────────────────────┐
│             │  文件分发                          │
│  目标实例    │  将本地文件/文件夹批量分发到目标实例  │
│             │  [添加文件] [添加文件夹]            │
│  ☑ 默认      │                                    │
│    ☑ 实例A   │  ┌ 文件列表 / 进度卡片 ──────────┐ │
│    ☐ 实例B   │  │  （idle: 文件列表）             │ │
│  ☐ 边缘节点  │  │  （staging/dispatching: 进度）  │ │
│    ☐ 实例C   │  └────────────────────────────────┘ │
│             │  目标前缀 [________]  已选1实例 5文件 │
│             │                          [开始分发] │
└─────────────┴──────────────────────────────────┘
```

- **左侧栏**：目标实例树（分组折叠 + 实例勾选 + bucket 选择）
- **右侧主区**：页头 + 文件列表/进度卡片 + 提交栏

idle 阶段显示文件列表，提交后进度卡片替代文件列表位置显示（不滚动到底部）。

## 3. 选择文件

### 3.1 文件选择方式

| 方式 | 行为 | 实现 |
| --- | --- | --- |
| 添加文件 | `<input type="file" multiple>`，多选文件 | 浏览器原生 |
| 添加文件夹 | `<input type="file" webkitdirectory directory multiple>`，保留目录结构 | 浏览器原生 |

两种方式可混合使用，多次添加的文件累加到同一列表。

### 3.2 文件列表展示

- **单文件**：逐行展示，图标 + 文件名 + 大小 + 暂存状态。
- **文件夹聚合**：同一文件夹的文件聚合为一条可展开条目，显示文件夹名 + 内含文件数 + 总大小 + 整体状态。展开后显示子文件明细。
- **列表底部**：显示"共 N 项（X 个文件 + Y 个文件夹）"。

### 3.3 暂存上传（自动）

用户点击「开始分发」后，前端逐文件将文件暂存到后端磁盘：

- 逐文件调用上传接口，流式落盘到暂存目录。
- 每个文件暂存完成后打 ✅，暂存中显示进度百分比（XHR `onprogress`）。
- 单个文件暂存失败时标记 ❌ + 错误信息，不影响其他文件。
- 全部暂存完成后（至少有一个成功），进入分发执行阶段。

### 3.4 文件管理

- **移除文件**：每行右侧有移除按钮（×），可从列表中移除尚未分发或分发中的文件。分发进行中时不可移除。
- **objectKey 规则**：
  - 单文件：objectKey = 文件名
  - 文件夹内文件：objectKey = 相对路径（如 `layout/index.html`）
  - 最终落到 MinIO 的完整 key = `prefix/objectKey`（由后端 dispatcher 拼接，前端只传 objectKey）
- **同名去重**：同批次选了两个同名文件，列表中只保留最后一个。暂存后 objectKey 相同的，后上传的覆盖先上传的（MinIO PUT 覆盖语义）。
- **空文件夹**：`webkitdirectory` 选中空文件夹不产生文件，列表中不显示空文件夹条目。

## 4. 选择目标

### 4.1 实例树

以分组树结构展示全部实例，与实例管理页一致：

- 分组和实例按自然顺序排列，默认分组置顶。
- 仅展示 enabled 状态的实例（disabled 实例灰显且不可勾选）。
- 分组支持折叠/展开。
- 分组级全选：勾选分组 = 选中该组下所有 enabled 实例；半选状态（部分选中）显示 indeterminate。

### 4.2 Bucket 选择

每个选中的实例需指定目标 bucket：

- **单实例选 bucket**：选中实例后，在其行内显示 bucket 选择器。优先从该实例的 bucket 列表中选择（下拉菜单）；若获取 bucket 列表失败，回退为手动输入。
- **组级批量设 bucket**：当一个分组内有多个选中实例时，可在分组行设置"批量设 bucket"，将该组内所有选中实例的 bucket 统一设置（仅当所选实例有公共 bucket 时可用）。
- **bucket 列表加载**：选中实例时异步加载该实例的 bucket 列表，加载中显示 spinner，失败显示告警图标。
- **未指定 bucket**：提交时若某选中实例未指定 bucket，该实例的所有文件标记为失败（错误："未指定 bucket"），不阻断其他实例。

### 4.3 目标前缀

- 一个全局前缀输入框，适用于全部目标实例。
- 留空 = 上传到 bucket 根。
- 前缀经 `sanitizeObjectKey` 清洗（防路径遍历）。
- 最终 key = `prefix/objectKey`。

## 5. 分发执行

### 5.1 提交分发

点击「开始分发」后：

1. 前端校验：至少一个文件已暂存 + 至少一个目标实例已选中并指定 bucket。
2. 前端调用分发接口，提交文件列表（fileId + objectKey）+ 目标（groupIds / instanceIds / instanceBuckets / prefix）。
3. 后端返回 `taskId`，前端通过 SSE 订阅进度。

### 5.2 并发模型

- **实例维度并发**：默认 5 个实例同时分发（`DISPATCH_CONCURRENCY` 可配）。
- **实例内文件串行**：每个实例内按文件顺序逐个上传。
- 不同实例之间的文件上传相互独立，某实例失败不影响其他实例。

### 5.3 上传策略

| 文件大小 | 策略 |
| --- | --- |
| < 8MB（`MULTIPART_THRESHOLD`） | 单次 PUT 上传 |
| ≥ 8MB | S3 Multipart Upload（Initiate -> UploadPart ×N -> Complete） |

- Multipart 分片大小：5MB（`MULTIPART_PART_SIZE`）。
- Multipart 上传失败时自动 abort，清理已上传分片，避免 MinIO 残留孤儿分片。
- Content-Type 由后端显式指定（按扩展名推断），避免 SDK 追加 `;charset=utf-8` 导致 MinIO 预览失败。

### 5.4 同名对象覆盖

MinIO PUT 是覆盖语义。分发同名对象直接覆盖，不弹确认。

## 6. 分发进度

### 6.1 进度视图

提交后进度卡片替代文件列表位置显示（不滚动到底部），采用**实例维度聚合折叠**视图：

```
┌ 4. 分发进度 ─────────────────────────────────────────────┐
│  共 5 个文件  成功 12  失败 1            ⟳ 分发中        │
│  ████████████░░░░░░░░░░░░░░░░░░  60%                    │
│                                                            │
│  ▸ 实例 A  3/5 ████████░░░ 1失败                    [重试]│
│    ├ ✅ config.json        2.1KB   320ms                │
│    ├ ❌ logo.png           45KB    失败: Access Denied   │
│    └ ⏳ data.yaml          1.2KB   分发中...             │
│                                                            │
│  ▸ 实例 B  5/5 ████████████████                        │
└────────────────────────────────────────────────────────────┘
```

- **顶部汇总**：总数 / 成功 / 失败 + 总进度条。
- **实例级折叠**：每个目标实例一行，显示完成数/总数 + 迷你进度条 + 失败数。点击展开显示该实例内每个文件的状态。
- **文件级状态**：✅ 成功（附耗时）/ ❌ 失败（附错误信息，tooltip 详情）/ ⏳ 分发中 / ⬜ 等待中。

### 6.2 SSE 事件

统一任务架构的 SSE 事件（见技术03 TaskEvent 定义）：

| 事件 | 数据 | 说明 |
| --- | --- | --- |
| `queued` | `{ taskId, queuePosition }` | 任务进入队列 |
| `start` | `{ taskId }` | 任务开始执行 |
| `progress` | `{ taskId, objectKey, result: FileResult, instanceId? }` | 单个文件状态更新 |
| `phase` | `{ taskId, phase }` | 阶段切换（move 专用，分发不使用） |
| `complete` | `{ taskId, summary }` | 全部完成 |
| `cancelled` | `{ taskId, summary }` | 任务被取消 |
| `error` | `{ taskId, message }` | 任务级错误 |

### 6.3 任务保留

任务完成后在内存任务表中保留 30 分钟（`TASK_RETENTION_SECONDS`），供 SSE 重连恢复和任务查看器查询最近完成的任务。超过保留期后任务记录清除。

## 7. 分发取消

### 7.1 取消操作

- 分发进行中，提交栏的「开始分发」按钮变为「取消」按钮。
- 点击「取消」后调用取消接口，后端设置任务的 `cancelled` 标志。
- 取消后：
  - 已完成上传的文件保留在目标实例上（不回滚）。
  - 未开始上传的文件跳过。
  - 正在传输的大文件：abort Multipart Upload，清理已上传分片。
- 取消完成后 SSE 推送 `cancelled` 事件，携带已完成的汇总。

### 7.2 取消后的状态

- 进度视图显示"已取消"状态 + 已完成汇总。
- 取消的文件标记为"已跳过"，与"失败"区分。
- 可对已取消的任务中失败的实例发起重试。

## 8. 失败重试

- 分发完成后（含取消后），进度卡片中有失败文件的实例显示「重试」按钮。
- 点击「重试」：重新提交分发，文件列表为该实例的失败文件，目标收窄为该单实例 + 其 bucket。
- 新任务有新 taskId，进入队列执行。
- 重试仅在进度卡片可见时可用（用户尚未点击「后台继续」或「新建分发」）。页面重置为 idle 后重试不再可用。
- 任务查看器中的已完成任务不提供重试入口（原始文件在用户本地，后端暂存已清理）。

## 9. 统一任务架构与后台运行

### 9.1 统一任务框架

分发功能建立在统一的后端任务框架之上。该框架同时服务于文件分发和实例访问页的上传/复制/移动操作（后两者后续改造纳入）。

核心机制：

- **taskId 模式**：提交任务 -> 后端返回 taskId -> 前端通过 SSE 订阅进度。任务执行与 SSE 连接解绑，断线不中断、重连可恢复。
- **全局任务队列**：同一时刻只执行一个任务（FIFO）。用户提交任务后立即可以继续操作，任务在队列中排队等待执行。
- **暂存不排队**：上传/分发的暂存阶段（前端->后端传文件）不涉及 MinIO 操作，不进入执行队列，提交后立即开始。
- **任务保留**：任务完成后在内存任务表中保留 30 分钟（`TASK_RETENTION_SECONDS`），供 SSE 重连恢复和任务查看器查询最近完成的任务。

> 改造节奏：先建通用框架 + 分发（本需求），再改造 copy/move/upload（后续各自技术方案）。

### 9.2 后台继续

分发阶段中，用户可点击「后台继续」关闭/离开分发页面，任务在后端继续执行。

> 暂存阶段不能后台继续（前端 XHR，离开则中断）。暂存完成后进入分发阶段才可后台继续。

### 9.3 任务查看器入口

页面右上角导航栏（与主题切换按钮并列）常驻任务查看器入口按钮，全局可见（非分发页独占）：

| 状态 | 显示 |
| --- | --- |
| 无任务 | 静态图标，无角标 |
| 有执行中任务 | 转圈图标 + 角标数字（任务数） |
| 全部成功 | 图标变绿 + 角标，3 秒后角标消失 |
| 有失败 | 图标变红/黄 + 角标常驻 |

点击按钮打开任务查看器弹窗，三段式展示：

1. **执行中**：当前任务的概要（类型 + 进度条 + 百分比），可点击展开详情（实例级进度 + 文件明细），详情区 max-h-60 滚动
2. **排队中**：队列中的任务列表，每行显示类型 + 目标，可取消
3. **最近完成**：最近 10 条已完成任务（成功/失败/跳过数 + 完成时间）

弹窗 max-h-[80vh]，不超出视口。

### 9.4 交互行为

- 点击入口按钮 -> 打开任务查看器弹窗，查看执行中/排队中/最近完成的任务。
- 弹窗内执行中任务的概要行可点击展开详情（手风琴模式，同时只展开一个）。
- 排队中的任务可取消（从队列移除）。
- 正在执行的任务可取消（设置 cancelled 标志）。
- 有失败的任务完成后，入口按钮角标常驻，用户手动查看后角标消失。

### 9.5 任务队列

- 提交任务时，若当前有任务正在执行，新任务进入队列等待。
- 队列中的任务可取消（从队列移除，不执行）。
- 正在执行的任务可取消（设置 cancelled 标志，执行器在检查点停止）。
- 前端展示队列状态：当前执行中的任务 + 排队中的任务列表。

## 10. 暂存管理

### 10.1 暂存生命周期

- 暂存文件存放在 `UPLOAD_DIR`（默认 `server/data/uploads/`），每个文件一个子目录 `uf-<uuid>/<safeName>`。
- 元数据保存在内存 Map（进程重启丢失，磁盘文件仍在）。
- 分发完成后，暂存文件由定时清理任务按 TTL 自动清理，用户无需手动管理。

### 10.2 孤儿清理

- Nitro plugin 启动时清理一次 + 每 6 小时定时清理。
- 超过 `UPLOAD_TTL_HOURS`（默认 24h）的暂存文件删除。
- 内存 Map 没有记录的孤儿文件用目录 mtime 兜底判定。

### 10.3 大小限制

- `MAX_UPLOAD_SIZE`（默认 0 = 不限），超限返回 413。
- 路径安全：`sanitizeObjectKey` 防路径遍历（反斜杠归一化、去段首点、过滤 `..`）；`sanitizeFileName` 只取最后一段。

> 暂存磁盘管理面板（查看磁盘占用、手动清理、查看文件列表）不在本需求范围内，后续作为独立需求讨论。

## 11. 边界行为

### 11.1 实例离线/连通失败

- 分发执行时实例离线：对应文件标记失败 + 错误信息（如 "Connection refused"），不影响其他实例。
- 不在提交前做连通性预检（连通性测试在实例管理页已有），直接在分发过程中暴露错误。

### 11.2 目标 bucket 不存在

- 上传时返回 404 NoSuchBucket -> 该文件标记失败 + 错误信息。
- 不影响其他实例。

### 11.3 暂存阶段关闭页面

- 暂存阶段离开页面：取消未完成的暂存请求，已暂存的文件留在暂存目录（由 TTL 清理），不进入分发阶段。

### 11.4 分发阶段关闭页面

- 分发是后端异步任务，关闭页面不终止任务。
- 后台继续或关闭页面后，分发页重置为 idle 状态，不恢复上一个任务的进度视图。
- 通过任务查看器弹窗可查看执行中任务的进度。
- 若任务已完成，任务查看器"最近完成"区域可查结果（保留 30 分钟）。

### 11.5 大文件分发

- 暂存阶段：走 multipart/form-data，浏览器原生处理。
- 分发阶段：< 8MB 单次 PUT，≥ 8MB Multipart Upload。
- 进度粒度：SSE 在文件级推送，单文件内无细粒度进度。大文件可能"分发中"状态持续较久。

## 13. 环境变量配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `DISPATCH_CONCURRENCY` | 5 | 分发实例维度并发数（队列内单任务的并发度） |
| `MULTIPART_THRESHOLD` | 8MB | 大文件分片阈值 |
| `MULTIPART_PART_SIZE` | 5MB | 分片大小 |
| `UPLOAD_DIR` | `server/data/uploads` | 暂存目录 |
| `UPLOAD_TTL_HOURS` | 24 | 暂存文件保留时长（小时） |
| `MAX_UPLOAD_SIZE` | 0（不限） | 单文件最大字节 |
| `TASK_RETENTION_SECONDS` | 1800（30 分钟） | 完成任务在内存表中保留时长（秒），供 SSE 重连和任务查看器查询 |

> V1 先用环境变量。未来如有需要，可平滑迁移为"环境变量作为默认值 + 平台内系统设置覆盖"。
