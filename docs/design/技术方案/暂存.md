# 暂存

- **实现**: `server/utils/staging.ts`
- **清理插件**: `server/plugins/cleanup-uploads.ts`
- **HTTP**: `GET/DELETE /api/staging`（见 [reference/HTTP接口.md](../../reference/HTTP接口.md)）

上传与分发先把浏览器文件写到服务端磁盘，再由任务执行器读盘推送到对象存储。暂存不进任务队列。

## 磁盘布局

```text
UPLOAD_DIR/                    # 默认 server/data/uploads
  uf-<uuid>/
    <safeName>                 # sanitizeFileName(originalName) 仅最后一段
    meta.json                  # 元数据（见下）
```

- `fileId` = `uf-<uuid>`
- `MAX_UPLOAD_SIZE > 0` 时超限抛 413

## meta.json

```json
{
  "fileId": "uf-…",
  "objectKey": "…",
  "originalName": "…",
  "size": 123,
  "contentType": "…",
  "stagedAt": "ISO-8601"
}
```

进程内另有 `Map<fileId, StagedFile>`。`listStagedFiles`：先 Map，再扫 `uf-*` 目录读 meta 补全（重启后仍可列出）；无 meta 的目录用目录 `mtime` 兜底。

## 生命周期

| 时机 | 行为 |
|------|------|
| `stageFile` | Buffer 写盘 + 写 meta + 登记 Map |
| 任务结束 | 执行器 `removeStagedFile`（upload/dispatch，try-finally） |
| 用户删除 | `removeStagedFiles(ids)`；缺省 ids = 清空 |
| 定时清理 | 启动一次 + 每 **6 小时**；删 mtime 超过 `UPLOAD_TTL_HOURS`（默认 24h）的 `uf-*` |

`removeStagedFile` 校验 `fileId` 必须以 `uf-` 开头且不含路径分隔符，再 `rm -rf` 对应目录。

## 与任务的关系

1. 前端 `POST …/stage` 得 `fileId`
2. 提交任务时带 `{ fileId, objectKey }[]`
3. 执行器 `getStagedFiles(fileIds)` → `readFile(diskPath)` → PUT
4. 结束清理暂存；异常残留由 TTL 兜底
