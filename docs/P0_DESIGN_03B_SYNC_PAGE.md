# 提议 3B 交互设计文档：实例同步独立页面

> **范围**：独立的实例同步页面 `/ops/sync`，从零开始选源 + 选目标 + 看进度，一站式工作台。适合"明确知道要从某实例批量同步一批文件"的规划性场景。
>
> **与第一部分的关系**：本文档是第二部分（独立同步页面）；第一部分 `P0_DESIGN_03A_BROWSER_SYNC.md` 是浏览器内快捷同步（浏览时顺手同步场景）。两者共用同一套后端 API（`POST /api/sync` + `GET /api/sync/events`）。
>
> **不在本次范围**：
> - 浏览器内快捷同步（第一部分）
> - 定时同步（提议 10）
> - 同步历史持久化（依赖提议 2 的历史框架，后续统一实现）
> - 源端对象的修改/重命名（同步是只读源 + 写目标，不修改源端）
> - 双向同步 / 增量同步（本次为全量覆盖式同步，增量见提议 9）

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 替代"下载再上传"三步操作 | 当前要把 A 实例文件同步到 B/C/D，需先下载到本地再上传分发。同步功能一步到位 |
| 不落盘 | 源→目标流式直传，不占用暂存磁盘，大文件不受 UPLOAD_TTL 限制 |
| 进度体验一致 | 复用 dispatch 页的实例级聚合折叠进度视图 + SSE 推送，用户无需学新交互 |
| 两个入口覆盖不同时机 | 主动批量同步走独立页面；浏览时顺手同步走浏览器快捷入口 |

### 3.1 源区域（左侧）

源区域是**单实例浏览模式**（与对象浏览器 `/ops/browser` 一致），复用其"选实例→选bucket→前缀导航→对象列表+多选"交互：

| 元素 | 来源 | 说明 |
|---|---|---|
| 源实例下拉 | 复用 browser 页的实例 `NuxtSelectMenu` | 单选，选后加载该实例 bucket 列表 |
| 源 Bucket 下拉 | 复用 browser 页的 bucket 选择器 | 含 loading/error/降级输入三态 |
| 前缀跳转输入 + 跳转按钮 | 复用 browser 页 | 手输前缀跳转，含 sanitize（反斜杠归一化、去 `..`） |
| 面包屑 | 复用 browser 页 | 按 `/` 拆段，点击逐级返回 |
| 对象列表 | 复用 browser 页 | 手写 div 列表，文件夹/对象分行，checkbox + 图标 + font-mono 名称 + 大小 + 日期 |
| 全选 checkbox + 计数 | 复用 browser 页 | `selectedKeys` + `selectedPrefixes` 两个 Set |
| 加载更多 | 复用 browser 页 | ListObjectsV2 分页，continuationToken |

**源区域的选中产物**：
- `selectedKeys: Set<string>` - 勾选的具体对象 key（完整路径）
- `selectedPrefixes: Set<string>` - 勾选的文件夹前缀

### 3.2 目标区域（右侧）

目标区域复用 dispatch 页的实例树 + bucket 选择 + 前缀输入：

| 元素 | 来源 | 说明 |
|---|---|---|
| 实例树 | 复用 dispatch 页 | 组可展开/折叠，组级全选（含 indeterminate 半选），实例级勾选 |
| 实例级 bucket 选择器 | 复用 dispatch 页 | 每个选中实例独立选 bucket，含 loading/error/降级输入三态 |
| 组级批量 bucket | 复用 dispatch 页 | 组内选中实例 bucket 交集，一键批量设置 |
| 目标前缀 | 复用 dispatch 页 | `NuxtInput`，留空则同步到 bucket 根 |

**目标区域的选中产物**：
- `targetInstanceIds: Set<string>` - 目标实例 ID 集合
- `targetBuckets: Record<string, string>` - 按实例指定的 bucket
- `targetPrefix: string` - 目标前缀

### 3.3 提交栏

```
已选 2 项源对象 → 1 个目标实例    [开始同步]
```

- 左侧 `flex-1` 占位
- 中间汇总文本：源对象数 + 目标实例数
- 右侧主按钮 `NuxtButton size="lg" color="primary" icon="i-lucide-refresh-cw" label="开始同步"`

**提交前置校验**（不满足时按钮禁用 + tooltip）：

| 条件 | 说明 |
|---|---|
| 源实例已选 | `sourceInstanceId` 非空 |
| 源 bucket 已选 | `sourceBucket` 非空 |
| 源对象至少 1 项 | `selectedKeys.size + selectedPrefixes.size > 0` |
| 目标实例至少 1 个 | `targetInstanceIds.size > 0` |

| 源实例不在目标列表中 | 源实例 ID 不在 targetInstanceIds 中（见 5.1） |

## 4. 交互流程详解（独立页面）

### 4.1 第 1 步：选源实例 + bucket

1. 左侧顶部实例下拉选择一个实例（单选）。
2. 选中后自动加载该实例的 bucket 列表（`POST /api/instances/buckets`）。
3. 选择 bucket 后，自动列出根级对象/前缀（`POST /api/instances/objects/list`）。

### 4.2 第 2 步：浏览并勾选源对象

1. 通过前缀跳转或点击文件夹逐层导航（面包屑可逐级返回）。
2. 勾选要同步的对象和/或文件夹：
   - 勾选对象：加入 `selectedKeys`
   - 勾选文件夹前缀：加入 `selectedPrefixes`，表示递归同步该前缀下全部对象
   - 全选：选中当前列表页全部对象和前缀
3. 切换前缀时，已选的 `selectedKeys` 和 `selectedPrefixes` **保留**（用户可跨前缀累积选择）。

### 4.3 第 3 步：选目标实例 + bucket + 前缀

右侧实例树操作方式与 dispatch 页完全一致：
1. 展开组，勾选目标实例。
2. 为每个目标实例选择 bucket（或用组级批量设置）。
3. 填写目标前缀（可选，留空同步到 bucket 根）。

### 4.4 第 4 步：提交同步

点击「开始同步」，前端提交 `POST /api/sync`：

```json
{
  "source": {
    "instanceId": "inst-src",
    "bucket": "config",
    "prefix": "config/",
    "keys": ["config/app.json"],
    "prefixes": ["config/data/"]
  },
  "targets": {
    "instanceIds": ["inst-1", "inst-2"],
    "instanceBuckets": { "inst-1": "backup", "inst-2": "data" },
    "prefix": "2025-q3/"
  }
}
```

后端返回 `{ taskId }`，前端通过 SSE 订阅 `/api/sync/events?taskId=xxx`。

### 4.5 第 5 步：扫描阶段（后端两阶段展开）

提交后后端先递归展开前缀为具体对象列表，此阶段前端显示扫描状态：

```
┌ 同步进度 ──────────────────────────────────────────────────┐
│                                                            │
│  ⟳ 正在扫描源对象...                                        │
│  已发现 156 个对象                                          │
│                                                            │
└────────────────────────────────────────────────────────────┘
```

- 后端递归 `listObjects(prefix, delimiter='')` 展开所有 `sourcePrefixes`，合并 `sourceKeys`，去重后得到完整对象列表。
- 展开过程中通过 SSE 推送 `scan-progress` 事件，前端显示"已发现 N 个对象"（实时增长）。
- 扫描完成后推送 `scan-complete` 事件，携带完整对象列表 + 总数 + 总大小，前端进度条总数确定。

**扫描阶段的意义**：让进度条总数从一开始就准确，避免同步过程中总数动态跳动。

### 4.6 第 6 步：同步进度（SSE）

扫描完成后进入同步阶段，SSE 推送 `start` → `progress` ×N → `complete`，与 dispatch 完全一致：

```
┌ 同步进度 ──────────────────────────────────────────────────┐
│  共 247 个对象  成功 120  失败 3            ⟳ 同步中        │
│  ████████████░░░░░░░░░░░░░░░░░░░░░░░░  48%               │
│                                                            │
│  ▸ 实例1  120/247 ████████░░░░ 3失败                 [重试]│
│    ├ ✅ data/app.json        2.1KB   320ms                │
│    ├ ❌ data/config.json     0.8KB   失败: Access Denied   │
│    └ ⏳ data/logo.png        45KB    同步中...              │
│  ▾ 实例2  247/247 ██████████████████                     │
└────────────────────────────────────────────────────────────┘
```

**进度视图复用 dispatch 页模式**：
- 顶部汇总：总数 + 成功 + 失败 + 总进度条（`NuxtProgress`）
- 实例级折叠列表：每行一个目标实例，显示完成数/总数 + 进度条 + 失败数 badge + 重试按钮
- 点击实例行展开文件级状态：每行 fileIcon + objectKey + 状态图标（success/failed/running），`NuxtTooltip` 显示耗时/错误

**SSE 事件**：

| 事件 | 数据 | 说明 |
|---|---|---|
| `scan-progress` | `{ taskId, scannedCount }` | 扫描阶段，已发现对象数（可多次推送） |
| `scan-complete` | `{ taskId, files: SyncFileInfo[], totalCount, totalSize }` | 扫描完成，携带完整对象列表 |
| `start` | `{ taskId }` | 同步开始 |
| `progress` | `{ taskId, result: SyncResult }` | 单个文件同步完成（成功/失败） |
| `complete` | `{ taskId, summary: { total, success, failed } }` | 全部完成 |

### 4.7 第 7 步：完成

```
┌ 同步进度 ──────────────────────────────────────────────────┐
│  共 247 个对象  成功 244  失败 3           ✓ 已完成          │
│  ██████████████████████████████████████  100%             │
│                                                            │
│  ▸ 实例1  244/247 ██████████████████ 3失败           [重试]│
│  ▸ 实例2  247/247 ██████████████████                     │
│                                                            │
│                                            [发起新同步]     │
└────────────────────────────────────────────────────────────┘
```

- 全部完成后显示汇总，`isRunning = false`。
- 有失败项的实例可点「重试」--重新提交该实例的失败文件（见 5.3）。
- 点「发起新同步」重置页面状态，回到选择区。

## 5. 边界行为

### 5.1 源实例出现在目标列表中

**独立页面**：右侧实例树中，源实例行禁用勾选 + tooltip 提示"源实例不能作为同步目标"。视觉上灰色禁用，不阻断其他实例选择。

**浏览器快捷入口**：Modal 实例树同样禁用源实例行。

**设计理由**：源实例自己同步到自己无意义且浪费带宽。如果用户确实想在同一实例的不同 bucket 间复制，应使用对象浏览器的下载+上传。

### 5.2 目标 key 拼接规则（相对路径）

目标 key = `targetPrefix + 相对源浏览前缀的对象路径`。

具体规则：
- 用户在源实例浏览到前缀 `config/`，勾选了 `data/app.json`（对象）和 `data/`（文件夹前缀）。
- 目标前缀填 `2025-q3/`。
- 目标 key：
  - `config/data/app.json` → 目标 `2025-q3/data/app.json`（去掉源浏览前缀 `config/`，保留 `data/app.json` 子路径）
  - `data/` 前缀下的 `data/logo.png` → 目标 `2025-q3/logo.png`

**与 dispatch 一致**：dispatch 的 objectKey 本身就是相对路径（文件夹上传时为相对路径），prefix 拼前面。同步沿用此语义：源浏览前缀相当于"当前目录"，对象相对于当前目录的路径拼到目标前缀后。

**源浏览前缀为空（bucket 根）时**：对象 key 本身就是完整路径，直接拼到目标前缀后。如源根目录的 `config/app.json` → 目标 `2025-q3/config/app.json`。

### 5.3 失败重试

有失败项的实例可点「重试」按钮：
- 重新提交 `POST /api/sync`，source 不变，targets 收窄为该实例 + 该实例的失败文件 key 列表。
- 后端跳过扫描阶段（keys 已知），直接进入同步。
- 新任务有新 taskId，进度区切换为新任务的 SSE。

### 5.4 同步进行中关闭页面/刷新

- 同步是后端异步任务，关闭页面不会终止任务。
- 刷新后：如果任务仍在内存中（完成 60s 内），进度区恢复（通过 URL taskId 重新订阅 SSE）。如果已过期，显示"任务不存在或已过期"。
- **与 dispatch 一致**：不持久化，刷新前应等任务完成或记住 taskId。

### 5.5 大文件同步

- 小文件（<8MB）：源 `getObjectStream` → 目标单次预签名 PUT，body 为 Web ReadableStream，流式直传。
- 大文件（≥8MB）：源 `getObjectStream` → 流式分片器按 PART_SIZE 切分 → 目标 Multipart Upload（Initiate → UploadPart ×N → Complete），失败时自动 abort 清理。
- 进度粒度：SSE 在文件级推送，单文件内无细粒度进度。大文件可能"同步中"状态持续较久（与 dispatch 一致）。

### 5.6 源端对象不存在（扫描后消失）

扫描阶段列出的对象，在同步时可能已被删除（并发写入场景）：
- `getObjectStream` 返回 404 → 该文件标记 failed + error "源对象不存在"。
- 不影响其他文件同步。

### 5.7 源端对象数量上限保护

递归展开前缀时，如果对象数超过上限（如 10000 个），扫描阶段停止并提示：

```
⚠ 源对象数量过多（超过 10000 个），请缩小同步范围
```

- 不开始同步，回到选择区让用户调整。
- **与 cleanup 的 deleteByPrefixes 上限保护一致**。

### 5.8 目标 bucket 不存在

目标实例上不存在指定 bucket 时：
- 上传时返回 404 NoSuchBucket → 该文件标记 failed + error。
- 不影响其他实例（其他实例的 bucket 可能正常）。

## 8. 不实现的内容

| 不实现项 | 原因 |
|---|---|
| 双向同步 | 场景复杂，当前需求是单向"从源复制到目标" |
| 同步后自动校验（对比 ETag） | 增加复杂度，用户可通过对象浏览器手动核对；未来配合提议 9 增量分发时再加 |
| 源端对象预览（同步前查看内容） | 已有对象浏览器可预览，同步页面不重复 |
| 同步任务取消 | 后端 sync 框架（克隆自 dispatcher）目前不支持取消，后续如加取消能力再统一支持 |
| 拖拽源对象到目标区域 | 交互复杂且两栏布局不适合拖拽，checkbox 选择已足够 |
| 跨 region 同步的 endpoint 适配 | 源和目标的 region 各自从实例配置取，无需用户指定 |
