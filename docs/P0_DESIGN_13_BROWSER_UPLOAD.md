# 提议 13 交互设计文档：对象浏览器上传文件

> **范围**：在对象浏览器（`/ops/browser`）中支持将本地文件/文件夹上传到当前实例的当前 bucket。
>
> **核心原则**：单实例与多实例（分发页）的上传体验保持统一。底层完全复用现有的「暂存 + dispatch + SSE 进度」流水线，对象浏览器只做"目标收窄"（锁定当前实例 / bucket / 浏览前缀），不另造上传机制。
>
> **不在本次范围**：
> - 暂存池管理面板（提议 12）
> - 跨实例批量上传（继续走分发页 `/ops/dispatch`）
> - 上传到不同 bucket（必须上传到当前浏览的 bucket）

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 补全对象管理 CRUD | 对象浏览器目前只有浏览/预览/下载/删除，缺"写"这一环 |
| 体验统一 | 选文件、暂存、进度反馈的方式与分发页完全一致，用户无需学第二套操作 |
| 即用即走 | 点"上传"弹对话框 -> 选文件 -> 看进度 -> 完成 -> 刷新列表，不需要管理暂存池 |
| 零新增后端机制 | 后端 dispatch 已支持 `instanceIds + bucket + prefix`，对象浏览器只是传不同参数 |

---

## 2. 功能入口

### 2.1 入口位置

在对象浏览器第 3 步「浏览对象」的工具栏中，新增「上传」按钮：

```
┌ 3. 浏览对象 ──────────────────────────────────────────────────┐
│                                                                │
│  前缀跳转: [config/2025Q3/    ] [跳转] [↻]                    │
│  面包屑: config > 2025Q3 >                                    │
│                                                                │
│  ☑ 全选  已选 0/12 项                       [上传] [下载选中] [删除选中] │
│                                          ↑ 新增                 │
│  ┌──────────────────────────────────────────────────────────┐ │
│  │ 📁 logs/                              ...                │ │
│  │ 📄 device.json    4.5KB  2025-07-14  👁 ⬇ 🔗 🗑          │ │
│  │ 📄 config.json    2.1KB  2025-07-15  👁 ⬇ 🔗 🗑          │ │
│  └──────────────────────────────────────────────────────────┘ │
└────────────────────────────────────────────────────────────────┘
```

### 2.2 前置条件

「上传」按钮仅在以下条件全部满足时可点击：

| 条件 | 说明 |
|---|---|
| 已选实例 | `selectedInstanceId` 非空 |
| 已选 bucket | `selectedBucket` 非空 |
| 实例在线 | 连通性状态为正常（非离线/未知） |

未满足时按钮禁用 + tooltip 提示原因（如"请先选择实例和 bucket"）。

### 2.3 为什么是对话框而不是独立页面

| 维度 | 独立页面 | 对话框（选定） |
|---|---|---|
| 目标选择 | 需要重新选实例/bucket | 自动继承当前浏览上下文 |
| 操作流 | 离开浏览 -> 上传 -> 返回 | 不离开当前页面 |
| 与分发页定位 | 与 `/ops/dispatch` 重叠 | 轻量补充，分发页仍是批量主场 |

对象浏览器上传是"单实例即时操作"，对话框形态最轻量，且不与分发页的批量定位冲突。

## 4. 交互流程详解

### 4.1 第 1 步：打开对话框

用户点击工具栏「上传」按钮，弹出 `NuxtModal` 对话框。

**对话框头部显示目标上下文**（自动继承，不可编辑）：

| 字段 | 来源 | 示例 |
|---|---|---|
| 实例 | `selectedInstanceId` -> 实例名 + endpoint | 实例 1 (10.24.0.10:9000) |
| Bucket | `selectedBucket` | config |
| 前缀 | `currentPrefix`（当前面包屑路径） | config/2025Q3/ |

前缀留空时显示"（bucket 根目录）"。用户无法在此修改目标--要换目标就关掉对话框，在浏览器里切换实例/bucket/前缀后重新点上传。

### 4.2 第 2 步：选择文件

**选文件方式与分发页完全一致**：

| 按钮 | 行为 | 实现 |
|---|---|---|
| 添加文件 | `<input type="file" multiple>`，多选文件 | 同分发页 |
| 添加文件夹 | `<input type="file" webkitdirectory directory multiple>`，保留目录结构 | 同分发页 |

选中后展示文件列表，格式与分发页一致：
- **单文件**：逐行展示，图标 + 文件名 + 大小
- **文件夹聚合**：聚合为一条可展开条目，显示文件夹名 + 内含文件数
- 列表底部显示"共 N 项（X 个文件 + Y 个文件夹）"

**移除文件**：每行右侧有移除按钮（×），可从列表中移除尚未上传的文件。

**objectKey 规则**（与分发页一致）：
- 单文件：objectKey = 文件名
- 文件夹内文件：objectKey = 相对路径（如 `layout/index.html`）
- 最终落到 MinIO 的完整 key = `currentPrefix + objectKey`（由 dispatcher 拼接，前端只传 objectKey）

### 4.3 第 3 步：暂存上传（自动）

用户点击「开始上传」后，前端逐文件调用 `POST /api/uploads` 将文件暂存到磁盘：

```
对每个选中的文件:
  FormData { file, objectKey? }
  -> POST /api/uploads
  -> 返回 { id, name, objectKey, size, contentType, storedPath, uploadedAt }
```

**暂存进度**：对话框内显示"正在暂存... X/Y"，每个文件暂存完成后打 ✅。此阶段是浏览器 -> 平台服务器的上传，用 XHR `onprogress` 显示百分比。

**暂存失败**：单个文件暂存失败时标记 ❌ + 错误信息，不影响其他文件。全部暂存完成后，已暂存的文件进入第 4 步 dispatch。

### 4.4 第 4 步：分发到当前实例（自动）

暂存完成后，前端调用 `POST /api/dispatch`，参数收窄为单实例：

```json
{
  "files": [
    { "id": "uf-xxx", "objectKey": "device.json" },
    { "id": "uf-yyy", "objectKey": "config.json" },
    { "id": "uf-zzz", "objectKey": "layout/index.html" }
  ],
  "instanceIds": ["当前实例ID"],
  "groupIds": [],
  "bucket": "config",
  "prefix": "config/2025Q3/"
}
```

后端返回 `taskId`，前端通过 SSE 订阅进度。

### 4.5 第 5 步：分发进度（SSE）

**进度展示**：因为只有一个实例，不需要分发页的实例级折叠视图，简化为扁平文件列表：

```
┌ 上传进度 ──────────────────────────────────────────────────┐
│  上传中...                              1/3                │
│  ████████████░░░░░░░░░                                   │
│                                                            │
│  ✅ device.json                 4.5KB   已完成             │
│  ⏳ config.json                 2.1KB   上传中...          │
│  ⬜ layout/index.html           1.2KB   等待中             │
│                                                            │
│  ❌ layout/style.css            0.8KB   失败: Access Denied │
└────────────────────────────────────────────────────────────┘
```

**SSE 事件**（复用 `GET /api/dispatch/events`）：
- `start`：任务开始
- `progress`：每个文件上传完成（成功/失败）推送一条 `DispatchResult`
- `complete`：任务结束，携带汇总 `{ total, success, failed }`

**与分发页进度视图的差异**：
- 分发页：实例维度聚合折叠（多实例，每实例内文件列表）
- 对象浏览器：直接文件列表（单实例，无需聚合层）
- 底层 SSE 通道和事件格式完全相同

### 4.6 第 6 步：完成与刷新

**全部完成后**：

```
┌ 上传完成 ──────────────────────────────────────────────────┐
│  共 3 项，成功 2，失败 1                                    │
│                                                            │
│  ✅ device.json                 4.5KB   已完成             │
│  ✅ config.json                 2.1KB   已完成             │
│  ❌ layout/index.html           1.2KB   失败: Access Denied │
│                                                            │
│  [查看失败详情]              [关闭]                         │
└────────────────────────────────────────────────────────────┘
```

- 点击「关闭」：关闭对话框，自动刷新当前 bucket + 前缀下的对象列表（`loadObjects()`），新上传的文件立即出现
- 有失败项时：显示"查看失败详情"按钮，展开每项的错误信息
- 暂存文件用完即走 dispatch，dispatch 完成后由现有 cleanup plugin 按 TTL 自动清理磁盘暂存，用户无需管理

## 5. 边界行为

### 5.1 同名对象覆盖

MinIO PUT 是覆盖语义。上传同名对象会直接覆盖，不弹确认。

**设计理由**：分发页也是覆盖语义且不确认；对象浏览器上传定位是"快速补传"，加确认会打断流程。如果用户需要谨慎操作，应先在浏览器列表确认同名对象是否存在。

### 5.2 上传进行中关闭对话框

- 暂存阶段关闭：取消未完成的暂存请求，已暂存的文件留在暂存池（由 TTL 清理），对话框关闭
- dispatch 阶段关闭：**dispatch 是后端异步任务，关闭对话框不会终止任务**。显示一次性提示"上传任务已在后台执行，关闭不会中断"。关闭后任务继续跑，用户可刷新列表查看结果
- 重新打开对话框时：不感知上一个任务状态（前端关闭后已释放 SSE 连接和任务信息），直接进入全新的选文件流程。上一个任务如仍在后台执行，用户可通过刷新对象列表查看结果

### 5.3 空文件夹上传

`webkitdirectory` 选中空文件夹时，不会产生任何文件，列表中不显示空文件夹条目（与分发页一致）。

### 5.4 objectKey 冲突（同批次内重复文件）

同一批次选了两个同名文件（如两个 `config.json`）：
- 暂存阶段：各自暂存成功（磁盘 storedPath 不同，id 不同）
- dispatch 阶段：objectKey 相同，后上传的覆盖先上传的
- 前端列表：去重展示，只保留最后一个同 objectKey 的条目（与分发页一致）

### 5.5 大文件上传

- 暂存阶段：走 multipart/form-data，浏览器原生处理，无大小限制（受 Nginx `client_max_body_size 0` 配置）
- dispatch 阶段：`uploadObject` 自动判断，<8MB 走单次 PUT，≥8MB 走 Multipart Upload（Initiate -> UploadPart ×N -> Complete），失败时自动 abort 清理
- 进度：暂存阶段有 XHR 百分比；dispatch 阶段 SSE 只在文件级粒度推送（单文件内无细粒度进度），大文件可能"上传中"状态持续较久

### 5.6 实例离线/连通失败

- 打开对话框时实例已离线：按钮禁用（见 2.2 前置条件）
- dispatch 阶段实例离线：对应文件标记失败 + 错误信息（如"Connection refused"），其他行为不变

## 6. 与分发页的体验对照

| 环节 | 分发页 `/ops/dispatch` | 对象浏览器上传对话框 |
|---|---|---|
| 选文件 | 添加文件 + 添加文件夹 | **完全相同** |
| 文件列表展示 | 单文件逐行 + 文件夹聚合 | **完全相同** |
| 暂存上传 | `POST /api/uploads` 逐文件 | **完全相同** |
| 暂存进度 | XHR onprogress | **完全相同** |
| 提交分发 | `POST /api/dispatch`（多实例） | `POST /api/dispatch`（单实例 + bucket + prefix） |
| 进度反馈 | SSE，实例级聚合折叠 | SSE，扁平文件列表 |
| 完成后行为 | 显示汇总 | 显示汇总 + 刷新对象列表 |
| 目标选择 | 用户选实例组/实例/bucket | 自动继承当前浏览上下文 |
| 暂存管理 | 可见暂存池 | 不可见（用完即走） |

**核心统一点**：选文件、暂存、dispatch、SSE 四个环节完全复用，差异只在"目标参数"和"进度 UI 聚合层级"。

## 7. 状态机

```
                    ┌─────────┐
                    │  idle   │ ← 对话框未打开
                    └────┬────┘
                         │ 点击"上传"
                         ▼
                    ┌─────────┐
              ┌────►│ staging │ ← 暂存上传中（XHR onprogress）
              │     └────┬────┘
              │          │ 全部暂存完成
              │          ▼
              │     ┌─────────┐
              │     │dispatch │ ← dispatch 提交，SSE 订阅中
              │     └────┬────┘
              │          │ 收到 complete 事件
              │          ▼
              │     ┌─────────┐
              │     │  done   │ ← 显示汇总，可关闭
              │     └────┬────┘
              │          │ 点击"关闭"
              │          ▼
              │     ┌─────────┐
              └─────│refresh  │ ← loadObjects() 刷新列表
                    └─────────┘
```

**异常分支**：
- staging 阶段部分失败：标记失败项，成功的继续进入 dispatch
- dispatch 阶段部分失败：标记失败项，不影响已成功项
- 任意阶段用户关闭对话框：staging 取消未完成请求；dispatch 后台继续跑

## 8. 与其他提议的关系

| 关联提议 | 关系 | 说明 |
|---|---|---|
| 提议 1 对象浏览器 | 所属 | 本提议是对象浏览器的功能扩展，入口在对象浏览器页面内 |
| 提议 2 分发历史 | 无直接依赖 | 上传产生的 dispatch 任务会进入分发历史（如已实现），但本提议不依赖它 |
| 提议 12 暂存管理面板 | 互补 | 本提议暂存文件用完即走，不展示暂存池；提议 12 提供全局暂存盘管理 |
| 提议 3 实例间同步 | 无重叠 | 同步是从实例拉取，上传是从本地推送，方向不同 |

## 9. 不实现的内容

| 不实现项 | 原因 |
|---|---|
| 拖拽上传到对象列表 | 分发页未实现拖拽，为保持统一暂不加；后续可两页一起加 |
| 上传到多个 bucket | 对象浏览器是单 bucket 浏览，跨 bucket 上传走分发页 |
| 上传前同名对象检测 | PUT 是覆盖语义，检测会增加请求延迟且分发页也没有 |
| 上传取消（dispatch 阶段） | 后端 dispatch 目前不支持取消，后续如加取消能力再统一支持 |
| 细粒度进度（单文件内分片进度） | SSE 只在文件级推送，细粒度进度需改造 dispatch，收益不大 |
