# 统一任务架构

- **实现**: `server/utils/task-manager.ts`、`staging.ts`、`sse.ts`、`use-task-manager.ts`
- **执行器**: [任务执行器.md](任务执行器.md)

长操作（分发 / 上传 / 复制 / 移动）统一为后端任务：执行与 SSE 连接解绑，断线不中断，重连可恢复。

## 组件

```text
后端
  TaskManager          内存任务表 + FIFO 队列 + 订阅
  executors/           dispatch | upload | copy | move
  staging.ts           磁盘暂存（upload/dispatch 前置）
  s3.ts                S3 协议层
  SSE                  createSSEStream

前端
  useTaskManager()     useState 单例，subscribe / cancel
  TaskViewerButton     三段式：执行中 / 排队中 / 最近完成
  StagingManagerButton 暂存查看 / 删除
```

## 任务生命周期

```text
createTask → queued → running → done | cancelled | failed
                │
                └─ 内存保留 TASK_RETENTION_SECONDS 后清理
```

| 语义 | 行为 |
|------|------|
| 调度 | 全局 FIFO，同一时刻一个 `running` |
| 暂存 | 不进队列（不操作对象存储） |
| 取消·排队 | 移出队列 |
| 取消·执行中 | `cancelRequested`；执行器在文件边界停；未开始文件 `skipped` |
| 失败 | 单文件失败不置任务 `failed`；`done` 且 `summary.failed>0` 为部分失败 |
| 摘要 | `total / success / failed / skipped` |

## 上传策略

分发与上传均为：`readFile`（暂存磁盘）→ Buffer → `PutObject` 单次 PUT。不用 S3 Multipart。

## 进度与恢复

- SSE 事件：见 [reference/HTTP接口.md](../../reference/HTTP接口.md)
- 重连：`GET /api/tasks/:taskId/state` 返回含 `instanceProgress` / `fileProgress` 的快照
- 一任务可多订阅者；订阅断开不影响执行

## 运行时特性

| 项 | 行为 |
|----|------|
| 进程重启 | 任务表丢失；磁盘暂存保留，由 TTL 清理 |
| 内存 | 任务表只存元数据与进度，不存文件内容 |
| 跨任务冲突 | 不检测 |
