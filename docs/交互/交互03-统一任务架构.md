# 统一任务架构交互说明

> 覆盖范围：文件分发、上传、复制、移动四个操作的完整交互流程，以及全局任务查看器的交互设计。
>
> 对应技术方案：`docs/技术/技术03-统一任务架构与文件分发.md`

## 1. 设计原则

### 1.1 后端主导

所有文件操作由后端主导执行。用户提交操作后，后端创建任务并独立执行，不依赖前端连接。关闭页面、网络波动不影响任务执行。

### 1.2 提交即自由

用户提交任务后立即可以继续其他操作（浏览实例、管理配置、提交新任务）。任务在后端排队执行，进度通过任务查看器随时可查。

### 1.3 串行执行

同一时刻只执行一个任务，后续任务排队等待。避免并发冲突（尤其 move 的破坏性操作），同时简化实现。

### 1.4 失败透明

任何操作失败时，在进度中明确标记失败项 + 错误信息。不隐藏错误，不自动重试，用户决定是否手动重试。

## 2. 任务查看器

### 2.1 入口

任务查看器入口常驻在页面右上角导航栏，与主题切换按钮并列。所有页面均可见。

```
┌──────────────────────────────────────────────────────────┐
│  miniops  MinIO 批量运维平台          [任务] [🌙]        │
└──────────────────────────────────────────────────────────┘
```

### 2.2 入口按钮状态

角标反映**全局任务概览**（所有活跃 + 未查看的已完成任务），不是单个任务的状态：

| 全局状态 | 图标 | 角标 | 说明 |
|------|------|------|------|
| 无任务 | `list-checks` 静态 | 无 | 空闲态，低视觉权重 |
| 有执行中/排队中任务 | `loader-circle` 旋转 | 数字（活跃任务数） | 角标为 primary 色 |
| 所有任务完成且无失败 | `check-circle` 绿色 | `✓`，3 秒后消失 | 短暂提示成功 |
| 有失败/取消未查看 | `triangle-alert` 黄色 | `!` 常驻 | 需用户查看后消失 |

优先级：有活跃任务 > 有未查看失败/取消 > 全部成功 > 无任务。例如：任务 A 成功但任务 B 仍在执行，角标显示数字（蓝色），不显示对勾。

- 旋转动画只作用于图标本身，角标保持静止
- 角标颜色：执行中 primary 蓝、成功 success 绿、失败/取消 error 红

### 2.3 任务查看器弹窗

点击入口按钮打开弹窗（Popover），三段式布局：

```
┌ 任务查看器 ────────────────────────────────────┐
│                                                 │
│  ─ 执行中 ──────────────────────────────────── │
│  ⟳ 分发 -> 3 个实例                   60%  ▾  │
│  ████████████░░░░░  3/5                       │
│  成功 2 · 失败 1 · 跳过 0                      │
│  ┌─────────────────────────────────────────┐  │
│  │ 实例A  3/5 ████████░░  1失败            │  │
│  │  ├ ✅ config.json     2.1KB   320ms     │  │
│  │  ├ ❌ logo.png        45KB    Access    │  │
│  │  └ ⏳ data.yaml       1.2KB   分发中     │  │
│  │ 实例B  0/5 ░░░░░░░░░░                  │  │
│  │ 实例C  0/5 ░░░░░░░░░░                  │  │
│  └─────────────────────────────────────────┘  │
│  ↑ max-h-60，超出滚动                            │
│                                                 │
│  ─ 排队中（1）────────────────────────────── │
│  📋 复制 5 个对象  A/a -> A/b          [取消]   │
│                                                 │
│  ─ 最近完成 ──────────────────────────────── │
│  ✓  分发 10/10 成功                   2 分钟前  │
│  ⚠  复制 7/10，3 失败                5 分钟前  │
│  ⊘  分发已取消 5/10                  8 分钟前  │
│                                                 │
└─────────────────────────────────────────────────┘
 ↑ 弹窗 max-h-[80vh]，超出滚动
```

### 2.4 弹窗各区交互

#### 执行中

- 展示当前执行中任务的概要行：类型图标 + 任务描述 + 进度百分比 + 展开/收起箭头
- 概要行下方有进度条 + 成功/失败/跳过计数
- **点击概要行**展开/收起详情（手风琴模式：同时只展开一个）
- 展开后的详情区按操作类型不同：
  - **分发**：实例维度折叠列表，每个实例一行（完成数/总数 + 迷你进度条 + 失败数），展开显示文件明细
  - **上传**：扁平文件列表，每个文件一行（文件名 + 大小 + 状态 + 耗时）
  - **复制/移动**：扁平文件列表，同上传
- 详情区 `max-h-60`（240px），超出内部滚动

#### 排队中

- 每行一个排队任务：类型图标 + 任务描述 + 取消按钮
- 点击取消按钮从队列移除该任务（不执行）
- 排队任务不展开详情（尚未执行，无进度）

#### 最近完成

- 最多展示 10 条已完成任务
- 每行：结果图标（✅ 成功 / ⚠ 有失败 / ⊘ 已取消）+ 任务描述 + 成功/总数 + 完成时间
- 完成时间用相对时间（"刚刚"、"2 分钟前"、"1 小时前"）
- 超过 30 分钟的任务从后端清除，不再显示
- 点击已完成任务不展开（历史结果，无需交互）

#### 空状态

无任何任务时显示"暂无任务"。

### 2.5 弹窗尺寸约束

| 层级 | 最大高度 | 滚动行为 |
|------|---------|---------|
| 弹窗整体 | `80vh` | 三段内容总高超限时弹窗内部滚动 |
| 详情区 | `240px`（max-h-60） | 文件明细超出时详情区内部滚动 |
| 最近完成 | 10 条 | 超出不显示（后端 limit=10） |

## 3. 文件分发交互

### 3.1 页面布局

分发页面为独立页面，左右双栏布局：

```
┌─────────────┬──────────────────────────────────┐
│             │  文件分发                          │
│  目标实例    │  将本地文件/文件夹批量分发到目标实例  │
│             │  [添加文件] [添加文件夹]            │
│  ☑ 默认      │                                    │
│    ☑ 实例A   │  ┌ 文件列表 / 进度卡片 ──────────┐ │
│    ☐ 实例B   │  │                                │ │
│  ☐ 边缘节点  │  │  （idle: 文件列表）             │ │
│    ☐ 实例C   │  │  （staging/dispatching: 进度）  │ │
│             │  └────────────────────────────────┘ │
│             │  目标前缀 [________]  已选1实例 5文件 │
│             │                          [开始分发] │
└─────────────┴──────────────────────────────────┘
```

- **左侧栏**：目标实例树（分组折叠 + 实例勾选 + bucket 选择）
- **右侧主区**：页头 + 文件列表/进度卡片 + 提交栏

### 3.2 操作流程

```
选择文件 → 选择目标实例和 bucket → 点击「开始分发」
  → 暂存阶段（前端逐文件上传到后端磁盘）
  → 分发阶段（后端异步分发到各 MinIO 实例）
  → 完成
```

选文件和选目标无顺序依赖，可先选目标再选文件。

### 3.3 选择文件

| 方式 | 行为 |
|------|------|
| 添加文件 | 浏览器原生 `<input type="file" multiple>`，多选文件 |
| 添加文件夹 | 浏览器原生 `<input webkitdirectory>`，保留目录结构 |

两种方式可混合使用，多次添加累加到同一列表。

**文件列表展示**（idle 阶段）：

- 单文件逐行展示：图标 + 文件名 + 大小 + 移除按钮（×）
- 文件夹聚合为可展开条目：文件夹名 + 内含文件数 + 总大小
- 列表底部：共 N 项（X 个文件 + Y 个文件夹）
- 同名去重：同批次选了两个同名文件，只保留最后一个

### 3.4 选择目标

**实例树**：

- 分组树结构，与实例管理页一致
- 仅展示 enabled 状态的实例（disabled 灰显不可勾选）
- 分组级全选：勾选分组 = 选中该组下所有 enabled 实例
- 半选状态显示 indeterminate

**Bucket 选择**：

- 选中实例后，行内显示 bucket 选择器
- 优先从该实例的 bucket 列表中选择（下拉菜单）
- 获取失败回退为手动输入
- 分组级批量设 bucket：组内有多个选中实例时可批量设置

**目标前缀**：

- 一个全局前缀输入框，适用于全部目标实例
- 留空 = 上传到 bucket 根
- 最终 key = `prefix/objectKey`

### 3.5 暂存阶段

点击「开始分发」后进入暂存阶段。

**UI 变化**：

- 文件列表卡片切换为进度卡片（同位置，不滚动）
- 进度卡片标题：`暂存进度` + `暂存中` 徽标
- 进度卡片内容：扁平文件列表，每行显示文件名 + 大小 + 上传进度条 + 百分比
- 提交栏按钮：只有「取消暂存」（无「后台继续」--暂存是前端 XHR，离开则中断）
- 「添加文件」「添加文件夹」按钮禁用
- 左侧栏实例勾选和 bucket 选择禁用

**暂存阶段不能后台继续**：暂存是前端 XHR 上传，离开页面会中断。暂存完成后进入分发阶段才可后台继续。

**取消暂存**：回到 idle 状态，已暂存的文件留在后端磁盘（由 TTL 清理）。

### 3.6 分发阶段

暂存全部完成后自动进入分发阶段。

**UI 变化**：

- 进度卡片标题：`分发进度` + `分发中` 徽标
- 进度卡片内容切换为实例维度聚合视图：
  - 顶部汇总：总数 / 成功 / 失败 + 总进度条
  - 实例级折叠列表：每个实例一行（完成数/总数 + 迷你进度条 + 失败数）
  - 展开显示文件明细：✅ 成功（附耗时）/ ❌ 失败（附错误 tooltip）/ ⏳ 分发中 / ⬜ 等待中
- 提交栏按钮：「后台继续」+「取消分发」

**后台继续**：

- 点击后页面重置为 idle 状态（清空文件列表、进度矩阵，回到"新建分发"初始态）
- 任务在后端继续执行，不受影响
- 用户可离开分发页面，通过导航栏任务查看器查看进度
- 任务查看器弹窗中显示当前任务的执行中状态
- 用户重新进入分发页时是干净的 idle 状态，可发起新分发（排队等当前任务完成）

**取消分发**：

- 已完成上传的文件保留（不回滚）
- 未开始上传的文件跳过（标记 skipped）
- 正在传输的文件：等当前 PUT 完成后不再继续后续文件
- 取消后进度视图显示"已取消"状态 + 已完成汇总

### 3.7 分发完成

**全部成功**：

- 进度卡片状态图标变绿 ✅
- 提交栏按钮变为「新建分发」
- 任务查看器入口角标按全局状态显示（见 §2.2）：若无其他活跃任务，显示 `✓` 3 秒后消失

**有失败**：

- 进度卡片状态图标变黄 ⚠
- 失败的实例行显示「重试」按钮
- 提交栏按钮变为「新建分发」
- 任务查看器入口角标按全局状态显示（见 §2.2）：显示 `!` 常驻

**已取消**：

- 进度卡片状态图标变灰 ⊘
- 取消的文件标记为"已跳过"
- 未完成的实例可重试
- 提交栏按钮变为「新建分发」
- 任务查看器入口角标按全局状态显示（见 §2.2）：显示 `!` 常驻
- 取消的任务进入任务查看器"最近完成"区域（标记 ⊘，保留 30 分钟）

> 注意：角标状态反映全局任务概览，不是单个任务的结果。例如：任务 A 全部成功但队列中还有任务 B，角标显示数字（蓝色，表示有活跃任务）而非对勾。详见 §2.2。
>
> 注意：执行中取消（已开始执行后被取消）与排队中取消（从未执行）不同。执行中取消会进入"最近完成"，排队中取消直接消失（见 §7.2）。

### 3.8 失败重试

**仅限进度卡片上的重试**：分发完成后（含取消后），进度卡片中有失败文件的实例显示「重试」按钮。

- 点击「重试」：重新提交分发，文件列表为该实例的失败文件，目标收窄为该单实例 + 其 bucket
- 重试时前端内存中仍有完整的文件列表和目标信息，直接预填并重新暂存
- 新任务有新 taskId，进入队列执行

**重试的时效限制**：

- 重试仅在进度卡片可见时可用（用户尚未点击「后台继续」或「新建分发」）
- 一旦页面重置为 idle，进度卡片消失，重试机会不再可用
- 任务查看器中的已完成任务不提供重试入口（原始文件在用户本地，后端暂存已清理，无法重建任务）

## 4. 上传交互

### 4.1 与分发的区别

上传是"单实例分发"：

| 维度 | 分发 | 上传 |
|------|------|------|
| 目标 | 多实例、各自指定 bucket | 单实例、当前浏览的 bucket |
| 入口 | 分发页面 | 实例访问页对象浏览器工具栏 |
| 文件来源 | 本地文件 | 本地文件 |
| 后端执行 | DispatchExecutor（目标实例=N） | UploadExecutor（目标实例=1，复用 DispatchExecutor） |

### 4.2 操作流程

```
实例访问页 → 浏览到目标 bucket/prefix → 工具栏点击「上传」
  → 弹窗选择文件/文件夹 → 点击「开始上传」
  → 暂存阶段（前端逐文件上传到后端磁盘，弹窗内显示进度）
  → 后端异步上传到 MinIO（弹窗内显示进度 / 后台继续）
  → 完成
```

### 4.3 弹窗交互

**选择阶段**：

- 弹窗内选文件/文件夹（同分发）
- 显示文件列表
- 点击「开始上传」进入暂存

**暂存阶段**：

- 弹窗内显示扁平文件列表 + 上传进度条
- 弹窗不可关闭（`:dismissible=false`）
- 「取消」回到选择阶段

**上传阶段（后端执行）**：

- 弹窗内显示文件列表进度（✅/❌/⏳）
- 弹窗可关闭（「后台继续」）--任务在后端继续
- 关闭弹窗后通过任务查看器查看进度
- 完成后弹窗显示结果（若仍打开）

**后台继续**：

- 点击后关闭弹窗，任务在后端继续
- 任务查看器显示执行中状态
- 重新打开弹窗时不恢复进度（通过任务查看器查看）

### 4.4 完成后

- 全部成功：toast 提示 + 刷新对象列表
- 有失败：弹窗内显示失败项 + 错误信息，可重试

## 5. 复制交互

### 5.1 操作流程

```
实例访问页 → 选中对象 → 工具栏点击「复制」或对象操作按钮点击「复制」
  → 弹窗选择目标实例/bucket/prefix → 点击「开始复制」
  → 后端异步复制（弹窗内显示进度 / 后台继续）
  → 完成
```

复制没有暂存阶段（源数据在 MinIO 上，后端直接服务端复制）。

### 5.2 弹窗交互

**选择阶段**：

- 显示已选对象概要（N 个文件 + M 个文件夹）
- 选择目标实例 + bucket + prefix
- 点击「开始复制」提交任务

**执行阶段**：

- 提交后立即进入执行（无暂存阶段）
- 弹窗内显示扁平文件列表进度（✅/❌/⏳）
- 同实例：服务端复制（快，不传文件内容）
- 跨实例：GetObject -> PutObject 流式直传
- 「后台继续」可关闭弹窗，任务在后端继续

### 5.3 完成后

- 全部成功：toast 提示
- 有失败：弹窗内显示失败项 + 错误信息，可重试

## 6. 移动交互

### 6.1 与复制的区别

移动 = 复制 + 删除源对象（两阶段）。

### 6.2 操作流程

```
实例访问页 → 选中对象 → 工具栏点击「移动」
  → 弹窗选择目标实例/bucket/prefix → 点击「开始移动」
  → 后端异步执行：复制阶段 → 删除源阶段
  → 完成
```

### 6.3 弹窗交互

**执行阶段**：

- 复制阶段：同复制的进度展示
- 删除阶段：显示"正在删除源对象..."+ 删除进度
- 两个阶段在弹窗内用阶段标签区分（`复制中` / `删除源`）

**取消**：

- 复制阶段取消：已复制的对象保留在目标，源未删，等同于执行了一次部分复制
- 删除阶段取消：已复制的对象保留在目标，部分源已删，可能需要手动清理

### 6.4 完成后

- 全部成功：toast 提示 + 刷新对象列表（源对象已删）
- 有失败：弹窗内显示失败项 + 错误信息
- 移动失败后可能出现"源和目标都有副本"的中间状态，需用户手动检查

## 7. 任务队列交互

### 7.1 提交排队

- 提交任务时若当前有任务在执行，新任务进入队列
- 提交后立即返回 taskId，前端不需要等待
- 任务查看器弹窗"排队中"区域显示排队任务

### 7.2 队列中取消

- 排队中的任务可取消（从队列移除，不执行）
- 取消后任务消失，不进入"最近完成"

### 7.3 队列执行顺序

- FIFO：先提交先执行
- 前一个任务完成（成功/失败/取消）后，自动开始下一个

### 7.4 暂存不排队

- 上传/分发的暂存阶段不进入执行队列
- 暂存不涉及 MinIO 操作，不与正在执行的任务冲突
- 多个暂存可同时进行（不同操作各传各的文件到后端磁盘）
- 暂存完成后提交分发/上传任务时才进入执行队列

## 8. 后台运行交互

### 8.1 哪些操作可以后台运行

| 操作 | 暂存阶段 | 执行阶段 |
|------|---------|---------|
| 分发 | ❌ 不能（前端 XHR） | ✅ 可以（后端任务） |
| 上传 | ❌ 不能（前端 XHR） | ✅ 可以（后端任务） |
| 复制 | 无暂存阶段 | ✅ 可以（后端任务） |
| 移动 | 无暂存阶段 | ✅ 可以（后端任务） |

### 8.2 后台继续后的行为

- 分发页/弹窗重置为初始状态（idle），不再显示当前任务的进度
- 任务在后端继续执行，不受影响
- 导航栏任务查看器入口显示执行中状态（旋转图标 + 角标）
- 用户可进行任何其他操作
- 任务完成后任务查看器更新状态

### 8.3 查看进度

- 打开任务查看器弹窗可查看执行中任务的进度（概要 + 可展开详情）
- 分发页重置为 idle，不恢复上一个任务的进度视图（避免与新建分发冲突）
- 用户可在 idle 状态发起新分发（新任务排队等当前任务完成）
- 若任务已完成，从后端获取最终结果（保留期内）

## 9. 边界行为

### 9.1 实例离线

- 执行时实例离线：对应文件标记失败 + 错误信息（如 "Connection refused"）
- 不影响其他实例

### 9.2 目标 bucket 不存在

- 上传时返回 404 NoSuchBucket -> 该文件标记失败 + 错误信息
- 不影响其他实例

### 9.3 大文件

- 暂存阶段：走 multipart/form-data，浏览器原生处理
- 分发/上传阶段：任意大小均为单次 PUT（不引入 S3 Multipart Upload）
- 进度粒度：SSE 在文件级推送，单文件内无细粒度进度
- 大文件可能"分发中"状态持续较久

### 9.4 同名对象覆盖

MinIO PUT 是覆盖语义。分发/上传/复制同名对象直接覆盖，不弹确认。

### 9.5 进程重启

- TaskManager 是内存态，进程重启后所有任务丢失
- 暂存文件在磁盘上不丢（孤儿清理兜底）
- 重启后用户可重新提交
