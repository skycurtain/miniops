# 提议 3A 交互设计文档：浏览器内实例间文件同步

> **范围**：在对象浏览器（`/ops/browser`）中浏览文件时，勾选对象/文件夹后直接同步到其他 MinIO 实例，全程不离开浏览器页面。
>
> **核心原则**：源已由浏览器上下文确定，Modal 只做目标选择 + 进度展示。提交后 Modal 内展示同步进度；关闭 Modal 后任务后台继续，页面右下角悬浮指示器保持进度可见。后端任务框架与 SSE 模式克隆自 dispatcher.ts。
>
> **与第二部分的关系**：本文档是第一部分（浏览器内快捷同步）；第二部分 `P0_DESIGN_03B_SYNC_PAGE.md` 是独立同步页面（主动批量同步场景）。两者共用同一套后端 API（`POST /api/sync` + `GET /api/sync/events`）。
>
> **不在本次范围**：
> - 独立同步页面 `/ops/sync`（第二部分）
> - 定时同步（提议 10）
> - 同步历史持久化（依赖提议 2）
> - 双向同步 / 增量同步（本次为全量覆盖式同步，增量见提议 9）

---

## 1. 设计目标

| 目标 | 说明 |
|---|---|
| 替代"下载再上传"三步操作 | 浏览到文件 -> 勾选 -> 同步到其他实例，一步到位 |
| 不落盘 | 源->目标流式直传，不占用暂存磁盘，大文件不受 UPLOAD_TTL 限制 |
| 交互自包含 | 从选目标到看进度都在浏览器页面内完成，不跳转到其他页面 |
| 进度不丢失 | 关闭 Modal 后任务后台继续，悬浮指示器保持进度可见，可随时点开看详情 |

---

## 2. 功能入口

在对象浏览器 `/ops/browser` 的工具栏中，选中至少 1 个对象/文件夹后显示「同步到...」按钮：

```
☑ 全选  已选 2/12 项     [上传] [同步到...] [下载选中] [删除选中]
                                   ↑ 新增（仅选中对象时可见）
```

- 未选中任何对象时按钮不显示（与「下载选中」「删除选中」一致）。
- 按钮 `NuxtButton size="sm" color="primary" variant="outline" icon="i-lucide-refresh-cw" label="同步到..."`。

## 4. 关闭 Modal 后的悬浮进度指示器

点击「后台继续」关闭 Modal 后，页面右下角出现悬浮进度指示器：

```
                                                    ┌──────────────────┐
                                                    │  ⟳ 同步中 3/10   │
                                                    │  ██████░░░░ 30%  │
                                                    └──────────────────┘
```

### 4.1 状态流转

| 阶段 | 悬浮指示器显示 |
|---|---|
| 扫描中 | `⟳ 扫描中... N 个` |
| 同步中 | `⟳ 同步中 3/10` + 进度条 |
| 全部成功 | `✓ 同步完成 10/10`（3 秒后自动淡出消失） |
| 有失败 | `⚠ 同步完成 7/10，3 失败`（常驻，需手动关闭或点击查看详情） |

### 4.2 交互行为

- **点击悬浮指示器** -> 重新打开 Modal，恢复进度视图（实例×文件矩阵）。此时 Modal 底部仍显示「后台继续」和「关闭」按钮。
- **任务进行中**指示器常驻，不自动消失。
- **全部成功**时显示 3 秒后自动淡出。
- **有失败**时常驻不消失，点击可重新打开 Modal 查看 + 重试。手动关闭指示器后不再出现。
- 悬浮指示器固定在页面右下角（`fixed bottom-4 right-4`），不随页面滚动。

### 4.3 技术上的简化

同步任务状态完全由 SSE 维护，Modal 开关只是"是否展示进度详情"的开关，不影响任务执行。悬浮指示器读同一份进度数据，展示精简版。**不需要 URL 参数、不需要状态恢复逻辑**--这是相比之前方案最大的简化。

## 5. 交互流程详解

### 5.1 第 1 步：在浏览器中勾选对象

用户在 `/ops/browser` 正常浏览：选实例 -> 选 bucket -> 导航到前缀 -> 勾选对象/文件夹（browser 页已有完整多选能力）。

### 5.2 第 2 步：打开同步 Modal

点击工具栏「同步到...」-> 弹出 Modal，顶部显示已确定的源上下文（只读），主体是目标实例选择。

### 5.3 第 3 步：选择目标

- 展开组，勾选目标实例。源实例行禁用勾选 + 标记"源"badge（见 6.1）。
- 为每个目标实例选择 bucket（或用组级批量设置）。
- 填写目标前缀（可选，留空同步到 bucket 根）。

### 5.4 第 4 步：提交同步

点击「开始同步」-> `POST /api/sync`，body 中 source 由浏览器上下文填充：

```json
{
  "source": {
    "instanceId": "当前实例ID",
    "bucket": "当前bucket",
    "prefix": "当前浏览前缀",
    "keys": ["config/app.json", "config/logo.png"],
    "prefixes": ["config/data/"]
  },
  "targets": {
    "instanceIds": ["inst-2"],
    "instanceBuckets": { "inst-2": "backup" },
    "prefix": "2025-q3/"
  }
}
```

后端返回 `{ taskId }`，前端通过 SSE 订阅 `/api/sync/events?taskId=xxx`。

### 5.5 第 5 步：扫描阶段（后端两阶段展开）

提交后 Modal 切换到进度视图。后端先递归展开前缀为具体对象列表：

- 后端递归 `listObjects(prefix, delimiter='')` 展开所有 `sourcePrefixes`，合并 `sourceKeys`，去重后得到完整对象列表。
- 展开过程中通过 SSE 推送 `scan-progress` 事件，Modal 内显示"已发现 N 个对象"（实时增长）。
- 扫描完成后推送 `scan-complete` 事件，携带完整对象列表 + 总数 + 总大小，进度条总数确定。

### 5.6 第 6 步：同步进度（SSE）

扫描完成后进入同步阶段，SSE 推送 `start` -> `progress` ×N -> `complete`。Modal 内展示实例级折叠进度视图。

**SSE 事件**：

| 事件 | 数据 | 说明 |
|---|---|---|
| `scan-progress` | `{ taskId, scannedCount }` | 扫描阶段，已发现对象数（可多次推送） |
| `scan-complete` | `{ taskId, files: SyncFileInfo[], totalCount, totalSize }` | 扫描完成，携带完整对象列表 |
| `start` | `{ taskId }` | 同步开始 |
| `progress` | `{ taskId, result: SyncResult }` | 单个文件同步完成（成功/失败） |
| `complete` | `{ taskId, summary: { total, success, failed } }` | 全部完成 |

### 5.7 第 7 步：完成或后台继续

- **在 Modal 内等到完成**：显示汇总，点「关闭」关闭 Modal + 刷新对象列表。
- **点「后台继续」**：关闭 Modal，右下角悬浮指示器显示进度。点击指示器可重新打开 Modal。

## 6. 边界行为

### 6.1 源实例出现在目标列表中

Modal 内实例树中，源实例行禁用勾选 + 显示"源"badge（`NuxtBadge color="warning" variant="soft"`）。视觉上灰色禁用，不阻断其他实例选择。

**设计理由**：源实例自己同步到自己无意义且浪费带宽。如果用户确实想在同一实例的不同 bucket 间复制，应使用对象浏览器的下载+上传。

### 6.2 目标 key 拼接规则（相对路径）

目标 key = `targetPrefix + 相对源浏览前缀的对象路径`。

具体规则：
- 用户在源实例浏览到前缀 `config/`，勾选了 `data/app.json`（对象）和 `data/`（文件夹前缀）。
- 目标前缀填 `2025-q3/`。
- 目标 key：
  - `config/data/app.json` -> 目标 `2025-q3/data/app.json`（去掉源浏览前缀 `config/`，保留 `data/app.json` 子路径）
  - `data/` 前缀下的 `data/logo.png` -> 目标 `2025-q3/logo.png`

**与 dispatch 一致**：dispatch 的 objectKey 本身就是相对路径（文件夹上传时为相对路径），prefix 拼前面。同步沿用此语义。

**源浏览前缀为空（bucket 根）时**：对象 key 本身就是完整路径，直接拼到目标前缀后。如源根目录的 `config/app.json` -> 目标 `2025-q3/config/app.json`。

### 6.3 失败重试

有失败项的实例可点「重试」按钮：
- 重新提交 `POST /api/sync`，source 不变，targets 收窄为该实例 + 该实例的失败文件 key 列表。
- 后端跳过扫描阶段（keys 已知），直接进入同步。
- 新任务有新 taskId，Modal 内进度区切换为新任务的 SSE。

### 6.4 关闭 Modal 后的行为

- **进度阶段点「后台继续」**：关闭 Modal，任务后台继续，右下角悬浮指示器显示进度。点击指示器可重新打开 Modal。
- **进度阶段点「关闭」**：仅在任务完成后可用。关闭 Modal 并刷新对象列表。
- **完成后点「关闭」**：关闭 Modal 并刷新对象列表。
- **重新打开 Modal**：通过点击悬浮指示器恢复进度视图。如果任务已完成，Modal 直接显示最终结果。
- **悬浮指示器手动关闭**：有失败时常驻，用户可手动关闭指示器（不重试）。关闭后不再出现。

### 6.5 大文件同步

- 小文件（<8MB）：源 `getObjectStream` -> 目标单次预签名 PUT，body 为 Web ReadableStream，流式直传。
- 大文件（≥8MB）：源 `getObjectStream` -> 流式分片器按 PART_SIZE 切分 -> 目标 Multipart Upload（Initiate -> UploadPart ×N -> Complete），失败时自动 abort 清理。
- 进度粒度：SSE 在文件级推送，单文件内无细粒度进度。大文件可能"同步中"状态持续较久（与 dispatch 一致）。

### 6.6 源端对象不存在（扫描后消失）

扫描阶段列出的对象，在同步时可能已被删除（并发写入场景）：
- `getObjectStream` 返回 404 -> 该文件标记 failed + error "源对象不存在"。
- 不影响其他文件同步。

### 6.7 源端对象数量上限保护

递归展开前缀时，如果对象数超过上限（如 10000 个），扫描阶段停止并提示：

```
⚠ 源对象数量过多（超过 10000 个），请缩小同步范围
```

- 任务以失败完成（complete 事件带空 summary），Modal 显示错误提示。
- **与 cleanup 的 deleteByPrefixes 上限保护一致**。

### 6.8 目标 bucket 不存在

目标实例上不存在指定 bucket 时：
- 上传时返回 404 NoSuchBucket -> 该文件标记 failed + error。
- 不影响其他实例（如果选了多个目标实例）。

### 6.9 同时发起多个同步任务

- 同一时刻只能有一个同步任务在进行中（Modal 或悬浮指示器活跃时，「同步到...」按钮禁用）。
- 如果用户想发起新同步，需等当前任务完成或点「后台继续」后关闭悬浮指示器（放弃查看进度）。

## 9. 不实现的内容

| 不实现项 | 原因 |
|---|---|
| 独立同步页面 `/ops/sync` | 第二部分实现 |
| 双向同步 | 场景复杂，当前需求是单向"从源复制到目标" |
| 同步后自动校验（对比 ETag） | 增加复杂度，用户可通过对象浏览器手动核对 |
| 源端对象预览（同步前查看内容） | 已有对象浏览器可预览，Modal 内不重复 |
| 同步任务取消 | 后端 sync 框架目前不支持取消，后续如加取消能力再统一支持 |
| 多任务并行 | 同时只允许一个同步任务，避免用户混淆进度 |
| 跨 region 同步的 endpoint 适配 | 源和目标的 region 各自从实例配置取，无需用户指定 |
