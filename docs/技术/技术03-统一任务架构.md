# 统一任务架构技术方案

> 通用框架：TaskManager + 暂存管理 + SSE + 任务查看器 + useTaskManager + 任务 API。
>
> 四个操作的技术方案各自独立：
> - `docs/技术/技术04-文件分发.md`
> - `docs/技术/技术05-上传.md`
> - `docs/技术/技术06-复制.md`
> - `docs/技术/技术07-移动.md`
>
> 对应交互说明：`docs/交互/交互03-统一任务架构.md`

## 1. 背景与目标

实例访问页的 upload/copy/move 三个操作当前是"前端驱动"模型（绑连接），关闭页面即中断。文件分发是新功能，直接用后端任务架构。

本方案建立统一的后端任务框架，四个操作共用：

- 任务执行与 SSE 连接解绑，断线不中断、重连可恢复
- 全局任务队列，串行执行，暂存不排队
- navbar 常驻任务查看器入口，覆盖所有任务类型
- 跨类型冲突不检测（参照操作系统"不防逻辑冲突，失败时报错"设计哲学）

## 3. 类型定义（shared/schemas/task.ts）

前后端共享的任务类型：

```ts
/** 任务类型 */
export type TaskType = 'dispatch' | 'copy' | 'move' | 'upload'

/** 任务状态 */
export type TaskStatus = 'queued' | 'running' | 'done' | 'cancelled' | 'failed'

/** 文件级结果 */
export interface FileResult {
  status: 'success' | 'failed' | 'running' | 'pending' | 'skipped'
  duration?: number
  error?: string
}

/** 实例级进度（dispatch 专属） */
export interface InstanceProgress {
  instanceId: string
  instanceName: string
  bucket: string
  results: Record<string, FileResult>  // objectKey -> result
}

/** 扁平文件进度（copy/move/upload 通用） */
export interface FlatFileProgress {
  results: Record<string, FileResult>  // objectKey -> result
}

/** 任务摘要 */
export interface TaskSummary {
  total: number
  success: number
  failed: number
  skipped: number
}

/** 任务描述信息（用于任务查看器展示） */
export interface TaskDescription {
  type: TaskType
  label: string           // 如 "分发 -> 3 个实例"、"复制 5 个对象"
  detail?: string         // 如 "A/bucket-a -> A/bucket-b"
}

/** 任务状态快照（用于 SSE 重连恢复 + 任务查看器） */
export interface TaskState {
  taskId: string
  type: TaskType
  status: TaskStatus
  createdAt: number
  completedAt?: number
  description: TaskDescription
  summary: TaskSummary | null
  instanceProgress?: InstanceProgress[]   // dispatch 专属
  fileProgress?: FlatFileProgress         // copy/move/upload 专属
  currentPhase?: string                   // move 的 'copying' | 'deleting'
  queuePosition?: number                  // queued 时有意义
  viewed?: boolean                        // 是否已被用户查看（角标用）
}

/** SSE 事件类型 */
export type TaskEvent =
  | { event: 'queued'; data: { taskId: string; queuePosition: number } }
  | { event: 'start'; data: { taskId: string } }
  | { event: 'progress'; data: { taskId: string; objectKey: string; result: FileResult; instanceId?: string } }
  | { event: 'phase'; data: { taskId: string; phase: string } }
  | { event: 'complete'; data: { taskId: string; summary: TaskSummary } }
  | { event: 'cancelled'; data: { taskId: string; summary: TaskSummary } }
  | { event: 'error'; data: { taskId: string; message: string } }
```

## 4. TaskManager（server/utils/task-manager.ts）

模块级单例，仿照 `store.ts` 的 `writeChain` 模式：

```ts
interface Task {
  taskId: string
  description: TaskDescription
  status: TaskStatus
  createdAt: number
  completedAt?: number
  executor: TaskExecutor | null
  cancelRequested: boolean
  summary: TaskSummary | null
  instanceProgress: InstanceProgress[]
  fileProgress: FlatFileProgress
  currentPhase?: string
  subscribers: Set<(event: TaskEvent) => void>
}

interface TaskExecutor {
  execute(task: Task, emit: (event: TaskEvent) => void, isCancelled: () => boolean): Promise<void>
}

const tasks = new Map<string, Task>()
const queue: Task[] = []
let running: Task | null = null

const RETENTION_SECONDS = Number(process.env.TASK_RETENTION_SECONDS) || 1800

/** 创建任务，返回 taskId */
export function createTask(description: TaskDescription, executor: TaskExecutor): string

/** 订阅任务事件（SSE），返回取消订阅函数 */
export function subscribe(taskId: string, callback: (event: TaskEvent) => void): () => void

/** 获取任务状态快照 */
export function getTaskState(taskId: string): TaskState | null

/** 获取任务列表（任务查看器"最近完成"） */
export function listTasks(status?: TaskStatus, limit?: number): TaskState[]

/** 取消任务 */
export function cancelTask(taskId: string): boolean

/** 批量标记已查看（角标用） */
export function markViewed(taskIds: string[]): void
```

### 4.1 调度逻辑

```
createTask():
  1. 生成 taskId，创建 Task 对象，status = 'queued'
  2. 存入 tasks Map
  3. 如果 running 为空 -> 直接开始执行
  4. 否则 -> 入队 queue，通知订阅者 'queued' 事件（含队列位置）

processQueue():
  1. 从 queue 取出第一个 task -> running
  2. status = 'running'，通知 'start' 事件
  3. await executor.execute(task, emit, isCancelled)
  4. 根据 cancelRequested 设置 status = 'done' | 'cancelled' | 'failed'
  5. 记录 completedAt
  6. 通知 'complete' / 'cancelled' / 'error' 事件（summary 取 task.summary，executor 负责设置；若未设置则全零）
  7. running = null
  8. 如果 queue 非空 -> 递归 processQueue()
  9. scheduleCleanup(taskId)

subscribe(taskId):
  1. 找到 task，加入 task.subscribers
  2. 返回 unsubscribe 函数
  3. 订阅时立即推送当前状态快照（用于重连恢复）

cancelTask(taskId):
  1. 如果在 queue 中 -> 直接从 tasks Map 移除（不进入"最近完成"），通知 'cancelled' 事件
  2. 如果正在 running -> 设置 cancelRequested = true（执行器在检查点停止），任务终态为 cancelled，进入"最近完成"
  3. 返回是否成功

listTasks(status, limit):
  1. 过滤 tasks Map 中匹配 status 的任务（"最近完成"查询 status=done,failed,cancelled）
  2. 排除从未启动的任务（排队取消的直接移除了，不会出现）
  3. 按 completedAt 降序排列
  4. 取 limit 条（默认 10）

markViewed(taskId):
  1. 设置 task.viewed = true
  2. 通知订阅者状态更新（角标据此判断是否消失）

scheduleCleanup(taskId):
  1. setTimeout(RETENTION_SECONDS * 1000) 后删除 tasks Map 中的记录
```

### 4.2 关键设计点

- **emit 函数**：executor 调用 `emit(event)` 时，TaskManager 遍历 `task.subscribers` 逐个推送。subscriber 调用 try-catch 兜底，连接断开不影响任务执行。
- **重连恢复**：前端断线重连后调 `subscribe(taskId)`，立即推送当前状态快照，前端重建进度视图后接收增量事件。
- **任务清理**：完成后 30 分钟（`TASK_RETENTION_SECONDS`）定时清理。

## 5. 暂存管理（server/utils/staging.ts）

暂存是 upload 和 dispatch 共用的阶段：前端逐文件上传到后端磁盘。

### 孤儿清理（server/plugins/cleanup-uploads.ts）

- 启动时清理一次
- 每 6 小时定时清理
- 超过 `UPLOAD_TTL_HOURS`（默认 24h）的暂存文件删除
- 内存 Map 没有记录的孤儿文件用目录 mtime 兜底判定

| 路由 | 方法 | 说明 |
|------|------|------|
| `/api/tasks/:taskId/cancel` | POST | 取消任务 |
| `/api/tasks/viewed` | POST | 批量标记已查看（`{ taskIds: string[] }`） |
| `/api/tasks/:taskId/state` | GET | 查询任务状态快照（重连恢复） |
| `/api/tasks/:taskId/events` | GET | SSE 订阅进度（EventSource） |
| `/api/tasks` | GET | 任务列表（`?status=done,failed,cancelled&limit=10`） |
| `/api/staging` | GET | 列出全部暂存文件（`StagedFileListItem[]`） |
| `/api/staging` | DELETE | 删除暂存文件（`{ fileIds?: string[] }`，缺省清空全部） |

### SSE 端点关键设计

现有 copy/move 的 SSE 任务绑死连接（断连即终止）。新的 SSE 仅推送进度，任务执行不依赖连接。TaskManager 的 `subscribe` 内部处理连接断开（try-catch），任务继续执行。

前端用 `EventSource`（GET）订阅，比现有 copy-move-modal 的 `fetch + reader`（POST）更简洁。

## 7. 前端

### 7.1 useTaskManager（app/composables/use-task-manager.ts）

全局 composable，用 `useState` 实现跨组件单例共享：

```ts
export function useTaskManager() {
  const activeTask = useState<TaskState | null>('task-active', () => null)
  const queueTasks = useState<TaskState[]>('task-queue', () => [])
  const completedTasks = useState<TaskState[]>('task-completed', () => [])

  /** 订阅任务进度（SSE） */
  async function subscribeTask(taskId: string) {
    const state = await $fetch<TaskState>(`/api/tasks/${taskId}/state`)
    updateTaskState(state)
    // EventSource 订阅增量事件
    const es = new EventSource(`/api/tasks/${taskId}/events`)
    es.addEventListener('progress', ...)
    es.addEventListener('complete', ...)
    es.addEventListener('error', () => { /* 断线重连 */ })
  }

  /** 取消任务 */
  async function cancelTask(taskId: string) { ... }

  /** 拉取最近完成（打开任务查看器时调用） */
  async function fetchCompleted() { ... }

  /** 标记已查看（打开弹窗时调用，角标据此消失） */
  async function markViewed(taskIds: string[]) { ... }

  return { activeTask, queueTasks, completedTasks, subscribeTask, cancelTask, fetchCompleted, markViewed }
}
```

**finalize 终态处理**：任务结束（完成/取消/失败）时调用内部函数 `finalize(taskId, status, summary)`。关键顺序：

1. 把终态 `status` 写入 `activeTask`（让 `watch(activeTask)` 的组件先感知终态）
2. `nextTick` 后才清空 `activeTask`（确保 watch 在非 null 时触发一次终态处理，再清空）
3. 从 `queueTasks` 移除，置入 `completedTasks`（保留最近 20 条）

这是为解决"直接清空 activeTask 会导致监听组件错过终态"的问题。

**注意**：composable 在 `<script setup>` 顶层调用（项目规范）。

### 7.2 TaskViewerButton（app/components/task-viewer-button.vue）

常驻在 AppNavbar 右侧工具区（与 `NuxtColorModeButton` 并列）。用 `NuxtPopover` 实现弹窗。

**按钮状态**（角标反映全局任务概览，优先级：有活跃任务 > 有未查看失败/取消 > 全部成功 > 无任务）：

| 全局状态 | 图标 | 角标 | 说明 |
|------|------|------|------|
| 无任务 | `list-checks` 静态 | 无 | 空闲态 |
| 有执行中/排队中任务 | `loader-circle` 旋转（仅图标转，角标不转） | 数字（活跃任务数，primary 蓝） | 活跃任务含排队 |
| 所有任务完成且无失败 | `check-circle` 绿色 | `✓`（success 绿），3 秒后消失 | 短暂提示 |
| 有失败/取消未查看 | `triangle-alert` 黄色 | `!`（error 红）常驻 | 需用户查看后消失 |

**角标"未查看"机制**：

- TaskState 有 `viewed` 字段，任务完成时默认 `viewed = false`
- 用户打开任务查看器弹窗时，调用 `markViewed(taskId)` 将所有已完成任务标记为 `viewed = true`
- 角标判定：有活跃任务 -> 显示数字；否则有 `viewed = false` 的失败/取消任务 -> 显示 `!` 常驻；否则所有刚完成的任务都成功且未查看 -> 显示 `✓` 3 秒后消失；否则无角标
- 组合态示例：任务 A 成功但任务 B 仍在执行 -> 显示数字（蓝色），不显示对勾

**在 AppNavbar 中挂载**：

```vue
<!-- app/components/app-navbar.vue -->
<template>
  <NuxtDashboardNavbar :title="title">
    <template #leading>...</template>
    <template #right>
      <TaskViewerButton />
      <NuxtColorModeButton />
    </template>
  </NuxtDashboardNavbar>
</template>
```

**更新机制**：纯响应式，不用定时器轮询。

- `onMounted` 时调 `fetchCompleted()` 预加载最近完成列表
- 角标和列表靠 `useState` 驱动，任务事件经 `useTaskManager` 的 SSE 接线实时更新到 `activeTask`/`queueTasks`/`completedTasks`，组件自动响应
- 成功角标 `✓` 用 `setTimeout` 3 秒后消失；失败/取消角标 `!` 常驻至 `markViewed` 调用

**弹窗三段式布局**（NuxtPopover）：

- 弹窗 `max-h-[80vh] overflow-y-auto`
- 执行中：概要行（可点击展开详情，手风琴模式）+ 进度条
- 排队中：每行一个任务 + 取消按钮
- 最近完成：最多 10 条（`GET /api/tasks?status=done,failed,cancelled&limit=10`），含成功/失败/取消三种终态（排队取消的不含，因为直接从 Map 移除了）

## 11. 风险

### 进程重启

TaskManager 是内存态，进程重启后所有任务丢失。暂存文件在磁盘上不丢（孤儿清理兜底）。

### 内存压力

暂存文件经 Buffer 写入磁盘。当前实现下文件内容会短暂进入内存（单次写入即释放），TaskManager 内存表只存元数据和进度，不存文件内容。若未来需处理超大文件，可改回流式写盘。

### SSE 连接管理

每个任务可有多个 SSE 订阅者（多标签页）。订阅者断开时 try-catch 兜底，不影响任务执行。
